# notes：跨对象漂移

## 守护什么

一致性审计最常见的失效是**只核一条路径就下结论**：规则在常测的那条路径上成立，于是被判"成立"，而另一条同样能改变该状态的路径没有守护。本 case 用一条规则的三个入口检验这一点。

同时检验另外四类对象之间的漂移：规则完全没有实现、代码里的目录镜像少一项、说明文字里的计数落后于规格、实现里多出规格没写的行为。

## 为什么要有对照

只测"能不能发现不一致"，一个把所有条目都标成缺陷的实现也能满分。R3 在唯一的相关路径上正确实现，用来检验 skill 不误报。

## 怎么跑

见 `input.md` 的执行者说明。被试与判卷者必须是两个独立执行者；判据先写死再跑，跑完不改判据。
