# 判定与严重度

> Supporting reference for `consistency-audit`. 第三步逐条判定时读。

## 六种判定

| 判定 | 定义 | 证据要求 |
| --- | --- | --- |
| **部分成立** | 条目在一部分路径、位置或取值上成立，在另一部分不成立 | 成立的位置与不成立的位置**都要列**；不成立的一侧给出复现方式 |
| **相悖** | 实现与条目直接矛盾 | 条目原文与实现原文并列，指出冲突点 |
| **缺失** | 实现侧找不到任何对应 | **检索记录**：检索模式、检索范围、每个模式的命中数。没有检索记录不得判缺失 |
| **强于规定** | 实现施加了条目没有要求的限制或条件 | 实现原文 + 条目原文，说明多出的是什么 |
| **无法判定** | 条目含糊，不同读法会得出不同判定 | 写出至少两种读法，及各自会得出的判定 |
| **成立** | 全部路径、位置与取值都成立 | 列出核对过的每一处；只列一处的"成立"视为未核对 |

判定是封闭的六种，不加限定语。一个条目对照几个被核对对象，就拆成几行，每行一个判定。

### 容易判错的五种情况

1. **实现方式与条目字面不同，但效果成立。** 条目要求"至少保留一个"，实现在删除前计数也好、在状态变更处拦截也好，都可以是成立——判的是效果，不是写法。但每条能改变该状态的路径都要有拦截。
2. **"缺失"其实是没搜到。** 执行常藏在调用方、公共校验、基类、中间层或数据层约束里。判缺失前，至少搜过：字段名、状态值、条目里的关键名词、调用链上一层。
3. **"成立"其实只核了常测路径。** 一个状态往往能被多个动作改变：新建、编辑、停用、批量、导入、迁移、回滚。只核了其中一个动作的不能判"成立"：核全后再判，来不及核全的列入未核对清单。
4. **集合型条目缺了几项。** 目录、枚举、权限点这类集合，实现侧有对应但少了若干项的，判"部分成立"并列出差集；只有实现侧完全没有对应时才判"缺失"。
5. **执行可能在范围之外。** 条目的执行通常放在不在本次被核对范围内的层（调用方、网关、登录流程）时，不判"缺失"，列入未核对清单并写明原因。

### Oracle 自身的问题

| 情形 | 判定 |
| --- | --- |
| 两份 Oracle 对同一件事说法冲突 | "无法判定"，逐份 Oracle 写出按它会得出的判定，交用户裁定 |
| Oracle 过时，实现跟随了更新的裁定或另一份 Oracle | "相悖"，建议改文档 |
| 实现与 Oracle 不一致，但该偏离已在 Oracle 或偏离登记里登记 | 照常判定并标"已登记"；登记仍准确的，严重度不高于 P2；登记本身失实的，另列一条 |

## 两个方向

| 方向 | 含义 | 发现归属 |
| --- | --- | --- |
| **Oracle → 实现** | 条目要求的，实现有没有做到 | 前五种判定 |
| **实现 → Oracle** | 实现做了的，Oracle 有没有写 | 反方向一节 |

反方向的发现，默认是"文档该补"，除非这个额外行为与其它条目冲突。**反方向同样按后果定级**：没有后果时默认 P2，有数据丢失、越权这类后果时照下表定级。

## 严重度按后果定，不按与字面的距离定

| 级别 | 后果 |
| --- | --- |
| **P0** | 数据越权可见、关键约束可被绕过导致不可恢复状态、金额或结果错误、数据丢失或重复 |
| **P1** | 业务规则在某条可达路径上不成立；实现者照某一份文档实现会做错；验收或测试会把正确实现判错 |
| **P2** | 不影响行为的口径不一致（计数、名称、过时引用）；反方向中尚无冲突的额外行为 |
| **P3** | 措辞、注释、定位信息层面的不一致 |

**一条发现同时符合几行时，取最高的一级。** 例如计数不一致本身是 P2，但实现者照那份文档会做错时是 P1。

**再按可达性修正**：出问题的路径只在测试里被调用、或检索不到任何调用方的，定级降一档，并附调用方检索记录。

同一条目，实现方式与字面不同但效果成立的，不是发现；字面一致但在一条路径上失效的，按后果定级，通常不低于 P1。

## 独立反驳

P0 / P1 发现由派发方另起执行实例尝试推翻。报告里给每条 P0 / P1 留出"反驳结果"一栏；单独使用、无派发方时标"未经反驳"。
