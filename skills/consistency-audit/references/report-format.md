# 审计动作与报告

> Supporting reference for `consistency-audit`. 开始审计时读第 1 节，出报告时读第 2 节。

## 1. 三种审计动作

派发方会声明本次是哪一种。

| 动作 | 核对什么 |
| --- | --- |
| **独立审计** | 全部高后果条目 + 其余条目（或列入未核对）+ 反方向 |
| **定向复审** | 派发方给出的**全部未关闭条目**逐条复核，并对这些条目重新做全入口枚举——修复可能只修了一条路径；再检查修复触及的相邻条目 |
| **完整重审** | 与独立审计相同，从当前文件冷启动，不采信上一轮报告的判定 |

**复审与重审先冻结判定，再看旧条目。** 先按当前对象完成判定并写入报告，之后才读派发方给出的旧条目做核销。先看旧结论会被它牵着走，只去验证旧问题，漏掉新问题。

## 2. 报告结构

### 2.1 元信息

| 项 | 内容 |
| --- | --- |
| Oracle | 逐个文件路径与版本或 hash |
| 被核对对象 | 逐个路径与类别 |
| 审计快照 | 提交 hash 或文件 hash；工作区是否干净 |
| 审计动作 | 独立审计 / 定向复审 / 完整重审，以及派发方给出的变更等级 |
| 输出时间 | 日期与时间 |
| 领域补充规则 | 已加载哪个 Provider，或"未加载领域补充规则" |
| 输入缺项 | 单独使用时缺了哪项输入、按什么假设执行；没有时写"无" |
| 本轮未读清单 | 与本次核对相关、本轮没有读的文件或对象类，及原因；没有时写"无" |
| 条目核销表 | 派发方给出的全部未关闭条目：编号、当前状态（已修 / 部分修 / 未修 / 不再适用）、证据；首轮写"首轮，无旧条目" |

### 2.2 条目判定表

按判定分组，顺序固定：**部分成立 → 相悖 → 缺失 → 强于规定 → 无法判定 → 成立**。

| 编号 | 条目（原文 + 出处） | 判定 | 实现侧位置 | 证据等级 | 严重度 | 后果 | 引入批次 | 反驳结果 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |

"引入批次"写本批 / 既有 / 未知；是否本次引入不影响核不核，但影响修复归属。已登记偏离在判定后标"已登记"。

非"成立"的条目，表后逐条展开：证据定位、复现方式、检索记录（缺失时必附）、建议改哪一侧（实现 / 文档 / 交用户裁定）。每条写到**不回看报告正文也能判断**的程度——派发方会据此登记进问题登记表，报告原文之后会删除。

### 2.3 反方向

实现里有、Oracle 没写的行为：位置、行为、是否与其它条目冲突、严重度（按后果定，无后果默认 P2）。

### 2.3A 附带发现

核对中顺带看到的、与任何条目都无关的单个对象自身缺陷：位置、复现方式、后果、严重度。能关联到条目的不放这里，进判定表。

### 2.4 未核对清单

拆出但未核对的条目及原因，包括执行可能位于被核对范围之外的条目。"成立"只有阅读证据的高后果条目也列在这里。

### 2.5 临时改动与还原

探针、变异的清单，以及还原核验的命令与结果。

### 附录：命令与输出

脚本差集、检索、探针与变异的命令及其输出，按条目编号引用。正文只写结论与定位，原始输出放这里。

## 3. 审计者边界

- 对被核对对象只读，临时改动必须还原；临时文件只写在审计目录内的专用子目录
- 不修改问题登记表，不删除、不标记其它文件
- 新发现使用独立编号
- 同一份报告分多次写入时只追加顶层章节，不修改既有章节
- 不宣告"一致 / 通过 / 可推进"

## 4. 单独使用时

无派发方、由用户直接调用时，报告写完即结束；P0 / P1 标"未经反驳"；报告就是交付物，如何保存由用户决定。
