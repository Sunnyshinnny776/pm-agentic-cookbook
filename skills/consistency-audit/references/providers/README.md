# 领域 Provider

本目录放**领域特化**的核对要点。`SKILL.md` 与 `references/` 下的其余文件通篇不含领域名词；换一个业务领域，它们一字不改。

本轮未附带任何领域 Provider，本文件同时起占位作用。

## 加一个领域

```
references/providers/<domain>/
  consistency-appendix.md
```

`<domain>` 用短横线小写标识。领域内容只在这一层出现。

## 一份领域附录该供什么

| 供什么 | 为什么在 Provider |
| --- | --- |
| 该领域里**高后果条目**的常见形态（哪些约束一旦在某条路径失效就不可恢复） | 决定第一步"高后果全部核对"的范围，各领域不同 |
| 该领域里**同一状态的常见入口**（例如批量、导入、定时任务、审批回写） | 决定第二步全入口枚举时不漏哪类入口 |
| 该领域里**常被镜像的目录**（编码表、组织结构、权限目录这一类） | 决定哪些比对必须用脚本做差集 |
