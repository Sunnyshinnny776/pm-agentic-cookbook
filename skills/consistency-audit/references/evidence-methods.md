# 取证方法

> Supporting reference for `consistency-audit`. 第二步找实现位置、第五步选取证方法时读。

## 方法与适用

| 方法 | 做法 | 何时必做 |
| --- | --- | --- |
| **全入口枚举** | 以字段名、状态值、集合名为关键字检索全部写入点；再沿调用链上溯一层，找批量、导入、迁移、回滚这类非交互入口 | 任何针对代码的条目 |
| **逐格比对** | 用脚本从双方抽取集合、字段或矩阵，输出差集；报告附命令与输出 | 目录 ↔ 代码镜像；两份文档里的同一张表 |
| **同名同数追踪** | 检索一个名字或一个数在全部被核对对象中的出现处，逐处比对 | 计数、角色名、状态名、编码 |
| **引文回源** | 把文档里"依据某某原文"的引句到被引文件里逐字检索 | 文档引用了 Oracle 原文时 |
| **探针用例** | 写一个临时测试，走到被怀疑的那条路径，断言条目要求的结果 | 判"部分成立"或"相悖"的代码条目 |
| **变异核验** | 故意改坏实现（删一个校验、改一个取值），看现有测试是否变红 | 守护测试的期望值由被测对象同源生成时；判"成立"而证据只有测试全绿时。被核对范围内没有测试时不适用，在报告里写明未做 |
| **跑测试** | 运行相关测试与全量测试，记录命令与结果 | 用到测试结果作为证据时；结果不稳定要复跑并如实记录 |

## 检索记录的格式

每条"缺失"与每条代码条目的全入口枚举，附一张检索记录：

| 检索模式 | 范围 | 命中数 | 说明 |
| --- | --- | --- | --- |
| `fieldName` | `src/` | 5 | 3 处读、2 处写 |
| `STATE_VALUE` | `src/`、迁移脚本 | 1 | 仅在一个函数中赋值 |

没有命中也要写出来——"搜了什么、在哪、结果为零"与"没搜"在报告里必须可区分。

## 临时改动的还原

探针与变异都会改动工作区。

1. **开始前**：在审计目录内建一个专用子目录放探针与快照，不写到审计目录之外。没有版本库时，先对被核对对象做一次文件 hash 快照
2. **结束前**：删除全部探针，撤销全部临时修改
3. **核验**：有版本库时用状态命令核对工作区与开始时一致；没有时重新计算 hash，与开始时的快照比对。快照保留到核验完成再删
4. 在报告里写明临时改动的清单与还原核验的命令和结果

## 证据等级

报告里每条判定标明证据等级：

| 等级 | 含义 |
| --- | --- |
| **执行** | 由探针、变异或测试运行结果支撑 |
| **执行（替身）** | 被核对范围之外的依赖用替身代替后得到的执行结果；写明替身的取值从哪里推出。结论若依赖替身的取值，按"阅读"对待 |
| **脚本** | 由脚本差集或检索结果支撑 |
| **阅读** | 由人工读原文支撑 |

判"成立"只有"阅读"证据的高后果条目，在报告中单列，提示派发方是否需要补执行证据。
