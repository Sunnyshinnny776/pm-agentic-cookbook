# 准入四问执行清单

> 逐问执行，每问的结论写进《源材料准入报告》。四问全部有结论，才允许进入档位判定。

---

## 一、可读性

**判什么**：材料能否被完整、无损地提取成可引用的文本。

### 先给交付规格，再做体检

多数提取缺陷在材料交到手上之前就能避免。**开口要材料时一并说明怎么给**：

- **格式优先级：Markdown > 文档格式 > 结构化表格 > PDF > 截图。** 同一份内容有多种格式时要最靠前的那一种
- **PDF 是最后选择**——多栏错行、表格塌陷、字符损坏的风险最高。原件若有其他格式，要那个
- **截图里的数字不可引用**，只能当线索
- 平台上的文档**导出后提供文件，或提供可读取的访问方式**

这一步做到位，下面的体检多数会直接通过。

| 检查 | 通过判据 |
| --- | --- |
| 能否提取 | 每份材料都得到了可读文本，或明确记录为"不可提取" |
| 提取质量 | 抽查若干段落与原件比对：无错行、无乱码、无表格塌陷、无图表内容丢失 |
| 结构完整 | 章节层级、编号、表格边界在提取物中仍然可辨 |

**不通过时**：登记缺陷（哪份材料、哪一部分、什么症状），并指定替代读法——换导出格式、换提取工具、局部人工转录。

**典型失败**（照着找，比泛泛地"检查一下"有效）：合并单元格归属错乱、公式只剩缓存值、PDF 多栏错行与表格塌陷、图片中的表格数字不可靠。

**硬规则：不得用损坏的提取物当依据。** 一段错行的表格会安静地产出错误的字段口径，而且下游无法发现。

## 二、权威性

**判什么**：这份材料的结论能不能直接当规则用。

判的是**材料自身处于什么状态**，以及**用户怎么裁定**。不追究材料是谁写的——追究出身对使用者没有帮助，也答不上来。

| 检查 | 要点 |
| --- | --- |
| 定位 | 是决策依据，还是参考、草案、他人的做法汇编 |
| 自带标记 | 文件名或正文中是否有"待确认""草稿""初稿""讨论稿"字样 |
| 内在状态 | 正文里有没有未写完的句子、留着的问句、互相打架的备注——这些是工作稿的特征 |
| 时效 | 是否已被更新的材料取代。**个人攒的材料更容易留下好几个版本** |

**典型失败**：引用指向未提供的文档、同一对象存在多份材料且不知哪份现行、材料描述的是计划态而非实现态。

**不通过时**：整份降级为参考层，其结论一律标 **INFERRED**，直到用户裁定。

**权威度必须分层记录**，不能只有"是/否"。同一批材料里往往同时存在唯一权威正文、补充材料、待确认草稿三类，混用是后续矛盾的主要来源。

### 降级之后：把 INFERRED 项列出来给用户裁定

降级会让**整份材料**的结论都变成 INFERRED，可能是上百条。要求用户逐条核对上百条，实际结果是没人核对。**按是否真的存疑分两级**：

| 分级 | 处理 |
| --- | --- |
| **逐条裁定** | 有冲突、有缺陷、影响面大的。一条都不能省 |
| **整批确认** | 仅因材料状态而被连坐、内容本身无争议的。用户一句"这部分我确认无误"即可 |

判据是**这一条是否真的存疑**，与它出自哪份材料无关。

**用户口头确定，或在报告中标注确定，即视为 `CONFIRMED`。** 不需要更正式的动作——这是一个辅助工具，无权要求使用者承担形式化的责任。

**内容不因此软化。** 材料里的错误、不确定、缺漏，一律严肃直白地列出来。要放轻的是**请用户做什么**，不是**告诉用户什么**。

## 三、完备性：广度 × 深度

**判什么**：材料覆盖到哪里，以及每处讲到多深。

### 广度

列出材料覆盖的模块清单。缺的模块直接进广度缺口。

### 深度

对每个已覆盖模块，逐层判断讲到哪一层：

| 层 | 判据 |
| --- | --- |
| **业务流程** | 有没有说清谁在什么时候做什么、流转到谁 |
| **业务规则** | 有没有可判定的规则（条件、算法、约束），而不只是描述 |
| **字段与取值** | 关键对象的字段、取值范围、必填性、默认值 |
| **异常与边界** | 失败路径、并发、越权、数据缺失时怎么办 |

**深度是最容易出问题的一维**，因为它很少被写进任何清单。两边对同一个系统名称的理解可以差出好几个子域——一方以为是其中两个，另一方以为是四个。范围蔓延多数由此而来。

#### 每一格记三态，不是两态

| 记号 | 含义 |
| --- | --- |
| **有** | 材料里讲到了这一层 |
| **缺** | **材料该有却没有**，是真缺口 |
| **下游** | **本来就由后续阶段产出**，材料没有它不算缺陷 |

只用"有/无"两态会让一份合格的材料看起来不合格：**字段清单、状态机、实体关系是数据建模阶段的产出物**，一份写业务流程与业务规则的方案文档本来就不该有它们。两态记法下这些格子全是空的，矩阵读起来像材料不达标，而处置栏写的却是"设计阶段产出"——**矩阵与处置在讲两件事，且矩阵先入为主**。

分辨的问题是：**这一层是材料的作者应当交付的，还是后续阶段的执行者应当产出的？**

只有标「缺」的才进深度缺口清单。标「下游」的记在矩阵里即可，它是给后续阶段的工作量提示，不是要用户去补的东西。

### 缺口清单要求

- **广度缺口与深度缺口分开列**
- 深度缺口必须落到"**哪个模块缺哪一层**"，不写"细节不足"这类无法行动的描述
- 缺口清单就是后续的"**停下问人**"清单，每一条要么被补齐，要么被显式接受为本期不做

## 四、一致性

**判什么**：材料互相之间、材料与已有实现之间有无矛盾。

### 先统一术语，再判断冲突

不同团队对同一对象的叫法常常不一致。**术语不统一时，多数"矛盾"是假矛盾。** 先产出术语对照表，把同物异名合并、同名异物拆分，再进入下一步。

### 三类冲突分别处理

| 冲突 | 处理 |
| --- | --- |
| 材料 A 与材料 B 矛盾 | 按权威度分层裁决；同层级则进 UNRESOLVED |
| 材料与已有实现矛盾 | 实现是"是什么"的权威，材料是"应该是什么"的依据——**两者都记录，进 UNRESOLVED** |
| 材料内部自相矛盾 | 整份材料的权威度存疑，考虑降级 |

### 引用断链要查两个层级

**同一条规则，两个层级都要查**：

| 层级 | 症状 | 处理 |
| --- | --- | --- |
| **字段级** | 规则或公式里引用的名字，在材料中找不到对应定义；或引用名与定义名只是形似 | 逐处列出引用位置与影响范围，进 UNRESOLVED |
| **文档级** | 材料引用了另一份文档，而那份文档未被纳入范围 | 登记为断链引用，进物料清单请用户补，**绝不猜测被引用文档的内容** |

字段级断链常常是批量的——一个引用名失效可以让几十条规则同时无法解析，所以要**数清楚影响多少处**，而不只是记一条"有引用错误"。

**存量迭代时，判定基准是目标系统的实际语法，不是材料内部自洽。** 材料里前后一致的引用，到了目标系统里可能照样解析不了（引用的是分组名而非条目名、缺少目标系统要求的包裹符号、用了不存在的函数）；反过来，材料里看着断了的引用，目标系统可能本来就支持。**拿到目标系统的语法与函数清单之后，这一类冲突多半会自动消解**，所以它常常是一条取证项，而不是一条待裁定项。

**但目标系统尚不具备该能力时，这条基准不适用**——本次变更就是要新建那个能力，不存在可对照的语法，断链只能靠裁定消解。此时要在报告中**写明基准不适用的理由**，否则读者无法判断这些冲突是等取证还是等裁定。

**硬规则：禁止自行选一个信。** 冲突项一律进 UNRESOLVED 清单交用户裁定。自选一个信的代价是——被丢弃的那个口径可能才是对的，而没有任何记录能让后来者发现这次选择发生过。
