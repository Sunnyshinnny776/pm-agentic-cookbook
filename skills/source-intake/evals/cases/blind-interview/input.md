# input：无文档盲测访谈

> **本文件分两部分。** 「给被试的原话」以下的内容可以原样交给被试；**「给执行者的说明」一节绝不能进被试的上下文**——它含判定意图与答案线索。
> 装载 skill 时一并排除 `evals/`（见下方命令），否则被试会在自己的工作目录里看到 `expected-points.md`。

---


## 被试环境

**必须是干净目录**——不能有宿主项目的 `CLAUDE.md`、memory 或仓库，否则被试会从上下文里读到答案而非问出来。

```bash
mkdir -p ~/eval-blind/.claude/skills/source-intake
rsync -a --exclude 'evals/' --exclude 'dist/' \
      <kit>/skills/source-intake/ ~/eval-blind/.claude/skills/source-intake/
cd ~/eval-blind && claude
```

**`evals/` 必须排除。** 直接 `cp -r` 会把本目录下的 `expected-points.md` 一并拷进被试的工作目录——**判据里写着三条答案**，而被试通常一上来就列一遍 skill 的目录。`dist/` 一并排除：留着它等于给被试一份可整体加载的全文，分批加载就测不出来了。

重跑时先 `rm -rf ~/eval-blind` 清掉上一轮。

**不要贴 `dist/` 的通用 prompt。** 装成真 skill 才能一并测到"用户随口一说时它会不会自己起来"，以及 references 是否按阶段分批读。

## 开场语（原样发给被试，之后不再给任何提示）

> 我们要做一家连锁零售企业的年度采购计划任务管理，我这边没有现成文档，需求在我脑子里。你来问，我来答。

## 被访者提示卡（给扮演业务方的人，被试看不到）

**你知道全部答案，但你要像真实业务方那样答。四条规矩：**

1. **只答被问到的。** 不主动补充、不替它想下一个问题。它没问到的，就是它漏了。
2. **能含糊就含糊。** 第一次回答给粗线条，追问了才给细节。真实业务方不会一上来就交代清楚层级结构。
3. **抛解决方案，不抛需求。** 例如直接说"我们要一个能配置计划模板的页面"，而不是"我们的采购计划由门店编制、区域汇总审批"。它得自己往回追到真实意图。
4. **遇到预测性问题照真实反应答。** 被问"这个功能你会不会用"时给个模棱两可的答复——方法论明确说这类问题的答案不可信，本 case 顺带测它问不问这种问题。

**不要提示、不要纠正、不要因为它没问到而着急。** 漏问就是数据。

## 收口

被试产出《源材料准入报告》与《需求确认书》后停止。把两份产出、以及**它每一次追问的原话**交给判卷者。追问是关键证据——问得好不好全在追问里。
