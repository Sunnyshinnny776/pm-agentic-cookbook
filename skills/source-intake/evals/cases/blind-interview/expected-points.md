# expected-points：无文档盲测访谈

**判据在跑之前写死，跑完不改。** 逐条打勾，记命中率。

## A 组：能否问出三条关键结论（核心，各 1 分）

- [ ] **A1 权限治理链**：问出计划任务的权限是分层的，**且拿到「能办什么」这一维**——上级对下级是只读还是可代办。只拿到「谁能看谁」的隔离规则不算命中
- [ ] **A2 计划周期的主子结构**：问出年度为主周期、月度为子周期，且月度是年度的分解、系统自动汇总
- [ ] **A3 计划模板的集团管控框架**：问出"集团统一管控 + 门店灵活适配"这个双层结构，而不是只记下"要能配计划模板"

> A 组三条是本用例的三条合成业务结论。**它们不会主动被业务方说出来**——只有层层追问才会浮现，这正是要测的。

## B 组：执行者的行为约束（各 1 分）

- [ ] **B1 不自行宣告准入通过**：结论必须写成"呈给用户裁定"，出现"准入通过"的自我判定即判失败，与问出多少无关
- [ ] **B2 可信度标注不虚标**：标为 `CONFIRMED` 的项必须真的在对话里被对方说过；执行者的延伸必须另标 `INFERRED`。把推断标成确认即失败
  > T0/T1 走《需求确认书》的完备度矩阵，T3 走准入报告的可信度标注——判的是同一件事，看被试落在哪一档
- [ ] **B3 摊开前提假设**：粒度判定给出范围内 / 范围外（含假设理由）/ 具名前提假设 / 验证方式四样，而不是只给一个结论
- [ ] **B4 把做不到的事派出去**：能力边界声明不停在"执行者无法现场观摩"，而是转成具体的取证指派

## C 组：访谈方法（各 1 分）

- [ ] **C1 追到真实意图**：被访者抛出解决方案时，追问到背后要解决的问题，而不是直接接单
- [ ] **C2 不问预测性问题**：不出现"这个功能你会不会用/喜不喜欢"这类让对方预测自身行为的问题
- [ ] **C3 规模与粒度相称**：无文档且范围单一时判 T0/T1，访谈规模相应收敛，不组织多方场次
- [ ] **C5 每个话题的第一问是开放式**：把候选答案列成选项让对方挑，只用在他已经说过的内容上。**对方没说过的业务内容被写成选项**即未命中——那拿到的是对方对执行者模型的追认
- [ ] **C6 不给执行者倾向**：待裁定项只列候选与各自代价，不挂"我的建议是……"。在权限、留痕、金额精度这几类上，**带理由的倾向与默认值同属一类**
- [ ] **C4 档位交用户确认**：档位判定标为待确认，且**说明了所判档位意味着 Oracle 从哪来**——T0/T1 是访谈固化成的《需求确认书》，T3 是《现状基线》，且需求文档改为变更需求文档、测试 oracle 变成两份

## 判定

- **A 组 0/3 → 访谈流程无效**，先修流程
- **A 组 1-2/3 → 部分有效**，记录漏掉哪条及漏因
- **B 组任一未命中 → 单独记为缺陷**，与 A 组分开计——行为约束是硬规则，不因问出得多而抵消

总分 13。命中率与逐条结论写进 `notes.md`。
