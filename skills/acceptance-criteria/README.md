# acceptance-criteria — 业务验收标准

[English](README.en.md)

在已确认的Domain Model之后、PRD之前生成“什么算完成”的清单。每条标准由用户确认，下游用清单名称加编号引用；生成草稿不会自动推进PRD。

## 使用

提供范围、需求确认书或源材料索引、已确认模型的文件/版本和输出路径。修订清单时另提供既有清单与下游缺口。未确认模型或无法定位来源时，先补依据。

输出只有文首范围/依据/状态、按场景分节的五列主表、待确认清单和变更记录。主表为编号、场景、预期结果、来源、状态；来源写文档名称、章节号和节名。行状态为待确认、已确认、作废，编号只增不复用。

## 分工与回流

页面级细节由create-prd细化；旅程与测试数据由journey-audit阶段A和test-authoring生成。一致性核对归consistency-audit。下游发现上游缺漏，先暂停受影响工作、回改依据和清单，确认后同步引用；不能在下游另建权威标准副本。

提供已最终确认范围说明、所有关联已确认模型版本、清单路径及对应台账落点。每个范围一组产物，模块只索引；同范围修订沿用，确认定义与交付验收分开。

## Model Experience

| 项 | 消耗方式 |
| --- | --- |
| 常驻部分 | name与description，约175字符，用于发现验收清单生成/修订请求 |
| 按需加载 | 生成或修订业务完成标准时读取SKILL正文 |
| 二级加载 | 组织清单时读取templates/acceptance-criteria.md；无需默认读取其他skill或领域资料 |
| 上下文预算 | 正文约2985字（不含frontmatter），模板约690字；业务输入的大小另计 |

## 分发

目录形态读取SKILL与模板；通用Prompt包含两者。安装包不带evals或领域实例。构建命令：

```sh
python3 scripts/build.py
```

## 能力边界

清单可追溯、可逐条确认，不证明模型业务正确或实现通过验收。缺来源、值未知、依据冲突时保留待确认，不编值。确认人和推进决定由用户提供。
