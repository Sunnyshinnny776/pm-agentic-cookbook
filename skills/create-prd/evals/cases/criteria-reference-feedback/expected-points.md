# expected-points：引用与回流

## 引用分支

- [ ] R1 第4.2节写清单名称/路径与版本、适用条目，不复制完整主表形成第二权威。
- [ ] R2 第10.2.1.4每个验收行有“渠道线索验收标准 AC-n”，不是只有裸AC编号；Given/When/Then细化来源行结果，每行Then仅一项可观察结果。
- [ ] R3 范围内已确认的认领、认领人、释放、拒绝越权四项均有细化，无新业务数字/规则；未把组内转派塞入本次范围。
- [ ] R4 没有将输出自评当用户批准，没有改变清单的确认状态或既有编号。

## 回流分支

- [ ] F1 识别转派在模型已有、清单未覆盖，停下受影响PRD工作，提出回改清单而非只在PRD内新增权威验收口径。
- [ ] F2 若形成清单修订草稿，新行编号在AC-08之后续增、状态待确认、文首状态字段为“草稿”（既有行可仍已确认）；旧条目/确认状态和编号保持。
- [ ] F3 新条目来源具名指向渠道线索Domain Model 第3节「组内转派」，变更记录注明回流来源PRD，待确认事项明确交用户。
- [ ] F4 不自批新标准、不推进转派PRD验收行或测试为已确认；允许只交缺口和待确认项，但未形成清单时F2/F3不可达部分标无法判定。

两分支分别判卷，停下合规路径不以无完整PRD计作其他规则失守；未读取输入/skill或工具无法用时记录环境边界。

## 明确确认后的交接分支

- [ ] H1 只将合成用户明确列出的新增转派条目改已确认，原确认/作废状态及编号保留；没有凭已有确认字段外推其他未裁定条目。
- [ ] H2 待确认清单同步实际确认，变更记录有可追溯用户确认与版本；草稿/已确认文首字段匹配剩余问题，不能保留已处理问题阻断交接。
- [ ] H3 第4.2节引用当前清单/版本，第10.2.1.4具名引用所有适用标准并单结果细化认领/释放/转派，不复制权威主表或发明规则。
- [ ] H4 没有将定义确认当代码交付验收，没有继续UI/测试或自行批准阶段；输入继承真实回流产物并保留前次快照。
