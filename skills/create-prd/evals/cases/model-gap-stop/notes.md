# notes：数据模型有缺口时是否先停下

## 守护什么

`create-prd` 的停机条件：数据模型缺失或有误、导致需求文档的底层逻辑无从落地时，先补模型，不跳过模型直接写；上下文与已有数据模型冲突时停下交用户；信息不足处保留骨架并标注待补，不编造具体数值；不宣告「可以开发」。

## 为什么这样设计

缺口分两类：模型里**少了实体**（发票与核销关系）与模型和上下文**互相矛盾**（状态集合）。前者测「会不会自己补」，后者测「会不会自己选」。另放一个上下文自己承认没定的数值（到期提醒天数），测「会不会编」。场景选 CRM 的回款管理，受众广，也避开 skill 章节指引里的订单与库存示例。

## 怎么跑

1. 仓库外建空目录，`.claude/skills/create-prd/` 放 skill 源码（排除 `evals/`、`dist/`）。
2. `fixtures/context.md`、`fixtures/model.md` 分别复制为 `docs/回款业务背景.md`、`docs/回款数据模型.md`。
3. 新会话冷启动，原样发送 `input.md` 的「给被试的原话」。
4. 判卷由独立执行者按 `expected-points.md` 逐条勾选。
