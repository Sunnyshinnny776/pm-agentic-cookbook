# 审计维度全集（域无关）

> 本文件枚举 journey-audit 对一次用户旅程逐步核验的维度。每个维度给出:**核验内容**(域无关不变量措辞)、**判定预言来源(oracle)**(指向已确认标准及PRD/spec细化的*类型*,不写某一项目的规则本体)、**语义可判度**(纯语义快照能否判定;`partial`/`visual` 项链接 [coverage-boundary](coverage-boundary.md))。
>
> **复用边界(关键)**:本文件是**域无关引擎**,迁移到任何 B 端系统都**原样继承、不需改动**。维度只回答"核验哪种一致性、判定指向哪类标准及细化条款",**不复制任何具体项目的业务规则本体**。
>
> 项目特化全部外移到三处"换装面",迁移时只动它们:
> - **oracle-map**:维度 → 目标项目 PRD/spec 的章节锚点表。
> - **采集锚点**:目标项目的稳定 DOM 标记(通用规则见 capture-format)。
> - **baseline**:目标项目按维度归档的*具体规则实例*。
>
> 三者都放在领域 Provider `references/providers/<domain>/` 下(`oracle-map.md`、`capture-anchors.md`、`baseline.md`)。
>
> **判定以共同 oracle 为准**:每条核验内容对照已确认验收标准、目标模块PRD细化与宿主规则。下列各维度的PRD/spec来源是细化定位，不排除已确认标准。维度措辞与来源不一致时以来源为准；来源彼此冲突则报告冲突并交用户裁定，不自行择一。标准明确而细化不足时保留标准依据及上游缺口，仍核验可由标准和快照直接判定的项；所有来源均未规定或证据不足的项标「口径待确认」或「快照不可判定」，不推测缺少的细节。

## D01 流程可达性与完整性

- **核验内容**:旅程是否能沿 PRD 定义的流程从起点贯通至应达终点,无死端、无中断、无不可达节点;PRD 规定应出现的节点是否在旅程中实际出现。
- **oracle**:目标模块 PRD 的流程定义 / 状态机图与节点说明表(锚点见所加载 Provider 的 oracle-map;实例见其 baseline D01)。
- **可判度**:full(节点序列由快照路由/节点字段重建)。

## D02 状态机一致性

- **核验内容**:每一步展示的状态语义是否等于 PRD 状态机对该节点的应有状态;状态流转是否仅沿允许的边发生;PRD 定义的特殊态(如终止态、可恢复态)语义是否正确。
- **oracle**:目标模块 PRD 的状态机定义、流转边与特殊态语义(实例见 baseline D02)。
- **可判度**:full(状态来自状态徽标等语义文本)。

## D03 角色 × 节点权限边界

- **核验内容**:当前节点暴露的操作集是否与生效角色的权限一致;有无跨节点操作泄漏(不属于当前节点的操作出现在当前节点);**数据范围(查看)与功能权限(编辑/操作)是否被正确区分**——对数据范围内、但不在编辑权限内的数据,是否只给出 PRD 允许的查看、审批等操作。
- **oracle**:宿主 UI/UX spec(宿主契约 `host.specMap` 的 `ui-ux` 角色)中角色导航与数据范围的规则 + 目标模块 PRD 的数据隔离边界与功能权限矩阵(锚点见 oracle-map;实例见 baseline D03)。
- **可判度**:full(操作集与角色由快照可见操作/角色字段判定)。

## D04 角色切换与导航行为

- **核验内容**(系统支持切换生效角色或身份时适用):切换后是否落到宿主规则指定的目标(例如等价节点、回退顺序、无可达页面时的处理);导航与正文是否按生效角色重渲染;切换后的身份在刷新与前进后退后是否按宿主规则保持;不可达页面是否不作为导航目标暴露;切换后,新身份无权查看的数据(列表、详情、缓存值、弹窗,以及上一身份晚到的请求结果)是否都已不可见。
- **oracle**:宿主 UI/UX spec(`ui-ux` 角色)中角色切换与导航回退的规则(锚点见 oracle-map;实例见 baseline D04)。
- **可判度**:full。

## D05 数据范围隔离

- **核验内容**:各角色仅见其数据范围;各列表只含 PRD 分给它的数据;跨数据范围的操作符合 PRD 口径;无越权数据泄漏。
- **oracle**:宿主 UI/UX spec(`ui-ux` 角色)中列表分工的规则 + 目标模块 PRD 的列表分工口径(锚点见 oracle-map;实例见 baseline D05)。
- **可判度**:full。

## D06 字段级校验与表单规则

- **核验内容**:必填、格式、范围、依赖联动(级联下拉)、禁用条件、非法输入的拦截与报错;提交在非法态下被正确阻断。
- **oracle**:目标模块 PRD 字段定义与校验规则;宿主 UI/UX spec(`ui-ux` 角色)中的组件用法规则;`table-template-designer` references(级联/单元格)。
- **可判度**:partial(校验文案/禁用态可判;校验触发的瞬时高亮/抖动等视觉反馈见 coverage-boundary)。

## D07 CRUD 与操作后状态一致性

- **核验内容**:新增/编辑/删除/提交/审批/驳回后,列表与详情是否一致反映变更(状态、计数、合计等);操作后视图刷新与服务端状态一致。
- **oracle**:目标模块 PRD 的操作定义与操作后副作用(实例见 baseline D07)。
- **可判度**:full。

## D08 跨页面 / 跨实体数据一致性

- **核验内容**:同一数据在不同页面展示一致;**派生数值是否按 PRD 定义口径由组成项算出**,并与明细一致。
- **oracle**:目标模块 PRD 的汇总/聚合口径 + domain model(实例见 baseline D08)。
- **可判度**:full(数值为文本)。

## D09 操作可见性与可用性(enablement)

- **核验内容**:按当前状态 × 角色 × 数据条件,操作是否正确呈现/启用/禁用(状态门控:前置态未达成的操作应禁用/隐藏;PRD 规定的特例正确放行;批量操作按 PRD 规则启用)。
- **oracle**:目标模块 PRD 的状态门控操作定义;宿主 UI/UX spec(`ui-ux` 角色)中的操作图标规则(锚点见 oracle-map;实例见 baseline D09)。
- **可判度**:full(`disabled`/可见性可由快照判定)。

## D10 反馈与提示语义

- **核验内容**:成功/错误/警告/确认反馈是否在正确操作上、以正确分类与文案触发;执行后无法撤销的操作,执行前是否有确认;可撤销的操作是否需要确认、用确认框还是撤销提示,按宿主规则或 PRD 核验;PRD 或宿主规则要求给出反馈的操作是否都有反馈。
- **oracle**:宿主 UI/UX spec(`ui-ux` 角色)中的反馈消息规则(实例见 baseline D10)。
- **可判度**:partial(toast 等为瞬时态,须由录制器**按事件捕获**而非定时快照;视觉样式见 coverage-boundary)。

## D11 文案与术语一致性

- **核验内容**:UI 文案是否与 PRD 规范术语及最新更名一致;无遗留旧术语;展示名是否符合宿主的命名规则。
- **oracle**:宿主 UI/UX spec(`ui-ux` 角色)中的 UX 写作与命名规则 + 目标模块 PRD 变更记录中的术语更名条目(实例见 baseline D11)。
- **可判度**:full(文案为文本)。

## D12 空 / 异常 / 边界态

- **核验内容**:空列表态、零/空数据、加载→就绪、请求失败错误态、边界值(0、上限、越界)、无权限态是否按 PRD 与宿主规则渲染。
- **oracle**:目标模块 PRD 的异常处理;宿主 UI/UX spec(`ui-ux` 角色)中对空白页与无权限页的规则(锚点见 oracle-map;实例见 baseline D12)。
- **可判度**:partial(状态文案可判;空态插画/骨架视觉见 coverage-boundary)。

## D13 集成与回调驱动状态

- **核验内容**:外部审批/集成回调是否正确驱动状态流转;外部审批节点的发生次数与位置是否符合集成规则;外部流程标识与附件是否按集成规则可追溯。
- **oracle**:目标项目的集成 spec(`host.specMap` 的 `integration` 角色)+ 模块 PRD 的集成对接(实例见 baseline D13)。
- **可判度**:full(状态/标识为文本;回调可由模拟实现触发)。

## D14 列表 / 表格交互行为

- **核验内容**:排序、筛选、分页、批量多选、行内操作的呈现与行为是否符合宿主规则;行只读 vs 可编辑是否随权限、数据范围与状态正确切换。
- **oracle**:宿主 UI/UX spec(`ui-ux` 角色)中的组件用法、操作图标与列表查询规则(锚点见 oracle-map;实例见 baseline D14)。
- **可判度**:partial(结构/可用性可判;拖拽列宽、排序动效等见 coverage-boundary)。

## D15 流程序列与时点正确性

- **核验内容**:步骤是否按 PRD 强制偏序发生,不可跳过前置态;关键产物的生成时点是否落在 PRD 规定的前置审批通过之后,且由 PRD 规定的节点触发。
- **oracle**:目标模块 PRD 的状态机与时点定义(实例见 baseline D15)。
- **可判度**:full(由快照状态/操作时序判定)。

## 维度扩展规约

- 新增维度须给出:核验内容(域无关措辞)、oracle 来源(指向 PRD/spec 的*类型*,不内联规则)、语义可判度。
- 具体项目规则**不写进本文件**,归 Provider 的 baseline;章节锚点归 oracle-map;DOM 标记归 capture-anchors。
- 若新维度落入视觉/时序盲区,同时在 [coverage-boundary](coverage-boundary.md) 标注其不可判部分。
- 增补本文件后,用 `scripts/build.py` 重建 `dist/`。
