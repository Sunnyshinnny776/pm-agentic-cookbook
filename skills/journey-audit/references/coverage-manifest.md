# coverage-manifest(人工 E2E 覆盖清单生成规约)

> 阶段A 的产物规约:从已确认验收标准及PRD/spec细化的适用范围派生「人工 E2E 覆盖清单」，作为人工测试的执行单与阶段B覆盖度diff的基准。**只引用已确认验收标准清单与PRD/spec，不复制规则本体**；缺少可执行细化时暂停受影响规划并记录上游缺口，标准仍保留在覆盖对照中；阶段B保留标准可直接支持的判定，不推测缺少的细节。来源冲突交用户裁定，所有来源均未规定的点标「口径待确认」。

## 覆盖范围(减法)

```
人工 E2E 覆盖清单 = 已确认标准及PRD/spec细化的适用范围
                  − test-authoring(单测)已覆盖项     ← 降优先级/排除，非硬删
                  − 纯视觉盲区(转「需人工视觉复核」，不进旅程清单)
```

### ① 应覆盖范围(枚举来源)

先逐条登记范围内已确认标准，再从PRD/spec细化枚举可执行路径；所加载领域Provider的oracle-map(`references/providers/<domain>/oracle-map.md`)提供细化定位，不取代原始来源:
- **状态机**:节点 × 流转边(每条边 = 一个待覆盖转移)。
- **权限矩阵**:角色 × 节点 × 操作(每个"该/不该出现"的组合 = 一个待覆盖断言)。
- **流程图分支**:正常路径 + 驳回/回退/异常分支。
- **关键数据/边界条件**:汇总口径、边界值(0/上限/超预算)。

### ② 扣除单测已覆盖(复用既有 PRD 追溯约定)

不另造覆盖插桩。宿主测试规范(`host.specMap` 的 `testing` 角色)若要求每个测试**在文件头注释与 describe 标注所追溯的 PRD 章节**,据此:

1. 扫描宿主测试规范规定位置下的测试文件:提取头注释 `用例追溯:PRD <file> <章节>` 与 `describe('… (PRD <章节>)')` 中的 PRD 章节号(如 `10.2.6`)。
2. 读取模块测试报告(`<模块目录>/<host.processRecordsDir>/` 下的 `*_test_report.md`)的「追溯 PRD」列,得到已被用例覆盖的 PRD 条目集合。
3. 命中PRD章节只形成候选覆盖项；核对实际测试断言与具名标准的全部必要断言，确认覆盖的部分才标注「已由单测覆盖」并**降优先级或排除**，其余部分保留。

宿主测试规范没有这项追溯约定时跳过第 1 条,只用测试报告;两者都取不到时,在清单中注明「组件测试覆盖面未扣除」,不静默当作零覆盖。

> **非硬删**:被单测覆盖的若其失败模式属"跨页面/运行时才暴露"(如组件单测通过但跨页流转断裂),仍保留为低优先级人工项,避免静默漏。本质保留的是单测**结构上覆盖不到**的部分(跨页面导航、角色切换后渲染、真实状态流转)。

### ③ 扣除纯视觉盲区

落入 [coverage-boundary](coverage-boundary.md) A/C 组的项不进旅程清单,转「需人工视觉复核」清单单列。

## 优先级排序

- 按 **业务关键度 × 可测性** 排序去重 → 可执行的优先级清单(**非** 节点×角色×分支的笛卡尔积全排列)。
- 业务关键度对齐 P 分级口径(核心流程/数据正确性 > 关键规则 > 边界 > 优化)。

## 清单文档结构

每条覆盖项一行,字段如下:

| 字段 | 说明 |
| --- | --- |
| 旅程编号 | 稳定 ID(如 `JM-order-01`) |
| 覆盖的验收标准 | 清单名称加编号（可附路径/锚点），不可只写AC编号；PRD/spec提供细化，缺少细化时仍保留标准及缺口 |
| 涉及节点 | PRD 状态机节点(对齐 capture-format 的 `node`) |
| 角色 | 生效角色(取 PRD 的角色定义) |
| 前置数据 | 进入该旅程所需状态/数据 |
| 关键核验点 | 指向 audit-dimensions 维度编号 + 标准/PRD/spec条目 |
| 优先级 | P0–P3 |
| 取舍记录 | 「已由单测覆盖→降级/排除」或「视觉盲区→转人工复核」时注明 |

并附两份排除记录:**单测已覆盖排除表** 与 **视觉盲区转人工表**,保证减法过程可追溯、不静默丢项。

## 验收标准覆盖对照

附清单名称/路径/版本，对每条范围内已确认标准登记计划旅程、已由单测覆盖、转人工视觉核验或未覆盖及原因。已有测试的扣除须核其断言实际覆盖该标准，不能仅凭相同PRD章节推断整节已覆盖；跨页面/运行时部分仍保留。待确认/作废标准不当作已生效目标，但不得静默消失，单列其状态。

清单、PRD或模型有缺口/冲突时，停止相关规划并回改最上游依据，确认后同步引用。阶段B只报告缺口及标准级已审/未审覆盖，不自行修订规则或将“计划覆盖”当实际已审。标准级覆盖还要核该标准的全部必要断言，旅程引用一个编号不等于整条已验证。

## 产物落盘路径(阶段A↔阶段B 的握手锚点)

覆盖清单是两阶段共享的 artifact,须落盘到稳定可定位路径,供阶段B 做覆盖度 diff:

- 路径:`<模块目录>/<host.testsDir>/<前缀>_e2e_coverage_manifest.md`,解析方法见 `SKILL.md`「宿主路径」(与该模块既有测试用例规格同目录,测试报告在同模块的过程记录目录)。
- 阶段B 默认读取被审旅程所属模块的此文件作为 diff 基准;未找到时标「阶段A 清单缺失,covered/uncovered 不可计算」,不静默跳过。

## 与阶段B 的衔接

- 阶段B保留清单名称/版本与具名标准映射，同时以本清单的「旅程编号 × 涉及节点 × 角色」为基准,对实际录制旅程做覆盖度 diff,列出未覆盖项。
- 多次录制(不同角色/分支)产出的旅程可累计比对本清单(多旅程累计覆盖留待迭代)。
