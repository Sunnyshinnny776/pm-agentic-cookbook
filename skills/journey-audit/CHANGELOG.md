# CHANGELOG

## v0.2.1（2026-11-11）

- 明确已有任务授权下按宿主规则处理范围内修复与规定复核，无需重复确认；业务取舍、修改 Oracle 或扩范围仍交用户裁定，审计/测试发现不自行授予实现修改权。
- 补全英文 Model Experience 的上下文预算，通用引用与具体领域 Provider 分开计数，保持中文说明与实际分发内容对应。

## v0.2.0（2026-10-24）

- 破坏性：自动调用以当前目标或已采用工作流所需产出为依据；明确适用用 Allow，实质歧义用 Ask，明确不适用用 Deny。仅比较材料或完成一个任务不自动启动审计。
- 迁移：调用方保留已确认目标、范围与流程步骤；目标明确时照常自动执行，歧义只问一次并等待答复。既定审计的独立性、证据与报告要求保持。

## v0.1.0

- 首个公开版本。
- 以已确认验收标准、PRD 细化与提供的 spec 为 Oracle，对真实运行的原型做两段式审计。
- 阶段 A 在人工测试前生成按业务关键度排序的 E2E 覆盖清单；阶段 B 读取录制器产出的语义快照与回放脚本，按 D01–D15 维度核验并与覆盖清单做差集。
- 报告带 P0–P3 分级与裁定列，显式列出需人工视觉复核的盲区与未覆盖项。
- 宿主未声明 UI/UX 规则、原型按 `ui-generator` 默认规则生成时，可由调用方给出该默认规则作为 UI/UX 预言。
- 审计自己的产物时须由独立执行者冷启动执行。
- 打印与导出版式列为视觉复核边界，不依赖宿主的特定类名。
- `scripts/build.py` 生成通用 Prompt 与 `.skill` 安装包；安装包成员使用固定时间戳，重复构建结果一致。
