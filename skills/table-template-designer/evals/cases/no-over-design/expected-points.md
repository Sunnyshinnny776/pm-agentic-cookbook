# expected-points：列少时不过度设计

- [ ] **T1** 判断出列数少于 10，不使用冻结列
- [ ] **T2** 不使用多级表头与级联下拉
- [ ] **T3** 仍然遵循基本表格规范：标题行样式、边框一致、金额右对齐
- [ ] **T4** 业务列只用题面给出的 6 列（skill 规定的序号列不算新增）；题面没给的状态取值列为待确认或以明确标注的占位示意
- [ ] **T5** 交付前做了代码缺陷自查，并简述修了什么（或说明没有发现问题）

## 判定

- **T1、T2 是核心**：规范驱动的 skill 最常见的失效是把复杂表的全套规则套到简单表上。
