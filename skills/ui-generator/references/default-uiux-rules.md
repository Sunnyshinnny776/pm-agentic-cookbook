# 默认 UI/UX 规则

> Supporting reference for the `ui-generator` skill. 宿主没有提供 UI/UX 规则时使用；宿主给出了自己的规则，就以宿主规则为准，本文件不再适用。

本文件与设计令牌 `templates/tob_design_tokens.css` 配套：令牌给出颜色、间距、字号、圆角、阴影的取值，本文件给出页面怎么组织、组件怎么用、交互和文案怎么写。下文的样式类按 Tailwind 写：主色与中性色对应令牌中的同名色阶，状态色（绿、橙、红、蓝）使用 Tailwind 默认色板，与令牌中的状态色取值一致；字号按 Tailwind 默认字号，令牌取值与之相同。

## 1. 页面布局

- 页面根节点使用淡入动画；页面内大模块之间用 `space-y-6`，卡片内元素之间用 `space-y-4`，标准卡片内边距 `p-6`。
- 页面标题区用 `flex justify-between items-center`，标题 `text-2xl font-bold text-gray-800`；多个页面级按钮之间用 `gap-2` 或 `gap-3`。
- 全局外框与侧边栏已经显示当前模块层级时，标题区不再重复面包屑；只有页面内确有外框不提供的层级或往返路径时才加面包屑。
- 顶部关键指标用一条通栏展示，不拆成多张卡片：`flex divide-x divide-gray-100`，每项居中；标签 `text-sm text-gray-500 mb-2`，数值 `text-3xl font-bold text-gray-800`，最重要的一项可用 `text-primary-600` 与 `text-4xl`；不加装饰图标。
- 用户可选的工作上下文（期间、周期、组织等）要写明保存范围：个人且与组织相关的选择按「用户 + 组织」保存，不变成全组织的全局开关；切换组织时载入目标组织自己的上下文，互不覆盖；保存的选择已不可访问时回到写明的安全默认值，并记录回退来源。界面上可修改的上下文只是入口偏好：下游流程生成历史业务对象时，把当时所选的上下文与相关配置的 ID、版本冻结进对象快照。
- 按业务期间筛选时，用写明了端点开闭的区间重叠判断是否命中，不用当前日期或月份标签近似；完整覆盖、部分重叠、当前失效但历史重叠的记录用不同的状态标签。缺少必需的期间实例时显示阻断状态与恢复指引，不悄悄变成空结果。

## 2. 组件

- 统一组件能满足需要时，业务页面必须使用统一组件：`Button`（`primary`、`secondary`、`outline`、`danger`、`ghost`）、`Badge`（`success`、`warning`、`error`、`default`、`processing`）、`Card`、页面级 `PageTabs`、`Table`、反馈组件与列表查询组件。
- **按钮**：`primary` 用于页面主操作，`secondary` 用于次要的主动操作，`outline` 用于辅助或取消，`danger` 用于破坏性或阻断性操作，`ghost` 用于低优先级操作。禁用时设 `disabled` 并继承 `disabled:opacity-50 disabled:cursor-not-allowed`。触发异步命令的按钮在执行期间禁用并显示「处理中…」一类的进行中文案，防止重复提交。页面级按钮统一使用默认尺寸（`text-sm`、标准内边距），不单独改字号或高度，与行内表格或表单对齐的情况除外。
- **表单字段**：同一对象的新建、编辑、详情表达一致的必填与选填语义。必填项在标签后紧跟 `*`，值缺失或无效时用错误色，满足后变为中性灰；用户需要填写的非必填项标「（选填）」，计算结果、审计元数据、分组标题不加标记。条件必填随当前业务状态变化，控制值改变时标记、校验与依赖字段一起更新。表示同一区间的起止输入在桌面端放在同一行的两列里，不因相邻字段出现或消失而被拆开。
- **Badge**：只用来表示对象状态，不放长说明、恢复指引或错误详情；业务页面不自定义状态点、背景或状态色。
- **Card**：用于独立的业务模块，白底、`rounded-lg`、浅阴影、`border-gray-100`；除确实是重复项的卡片列表外，不在卡片里嵌套卡片。
- **页面级标签页**：只用于在页面标题下切换主视图，每个标签带 16px 图标与简短文字（`gap-2 px-6 py-3 text-sm font-medium`），选中项白底、主色文字、遮住底部分隔线 1px，并提供描述性的无障碍标签。抽屉分区、向导步骤、紧凑的内容分类切换不用它；标签页不得用来切换用户角色。
- **表格**：主列表表头用主色浅底（`bg-primary-50/70 text-primary-800 border-primary-100`），子表、抽屉预览表与行内展开明细用中性表头（`bg-gray-50 text-gray-500 border-gray-200`）并统一 `text-[13px]`。行 hover 用 `hover:bg-primary-50/30`。主列表单元格 `px-6 py-3`、`whitespace-nowrap`，容器 `overflow-x-auto`；紧凑表格 `px-4`。表格容器保留轻边框、圆角与行分隔线。
- **冻结列**：可横向滚动的主列表把左侧身份列（从第一列到主名称列）固定在左边，主名称列不透明并带右侧分隔阴影，各列声明固定宽度与累计左偏移；行操作是完成主任务所必需时，操作列固定在右边，不透明并带左侧分隔阴影。
- **列的取舍**：不为视觉统一而加序号列、勾选列、批量操作栏或操作列；分析矩阵可以直接从业务维度开始，只追加的审计日志可以没有勾选与操作列。
- **主列表容器**：列表标题、查询工具栏、批量操作栏、表格、分页放在同一个连续容器里，不拆成多张浮动卡片；标题区只显示列表标题（`text-base font-bold text-gray-800`，`px-6 py-4`，底部中性分隔线）；页面级新建操作放在查询工具栏右端。同一业务列表对所有有权访问的角色使用同一结构，角色差异只体现在数据范围、筛选项、可选行与可用操作上，不另做视觉变体。
- **分页**：主列表默认每页最多 10 行；无数据时显示「暂无数据」并隐藏分页；任何查询条件变化后回到第 1 页；行号按 `(当前页 - 1) × 每页条数 + 序号 + 1` 计算。
- **单元格内容**：数字与金额格式化；长文本可以截断并配提示；业务状态用 Badge；业务提示、错误与恢复指引用反馈组件。
- **层级筛选**：选择组织的筛选、下拉与树统一复用一份组织元数据，不在页面里另造组织数据。级联筛选选定上级后才出现下一级，下一级包含「全部下属」与上级本级；限定范围的角色只能在自己的子树内筛选。树选择展开成具体组织 ID 集合时，这个集合就是提交的业务范围，不再另设「仅所选 / 含下级」开关；根节点本身可作业务单位时单独列为一行，不因选满全部下级而被连带选中；确认前显示受影响的组织数。
- **提示框**：悬停提示统一用 `Tooltip` 组件，不用浏览器原生 `title` 属性；`text-[13px]`、圆角矩形、无指向箭头、灰色主题（`bg-gray-100/95 border-gray-200 text-gray-600`），悬停 0.5 秒后出现。

## 3. 列表查询

- 列表标题、上下文提示、查询工具栏、批量操作栏、表格与分页构成一个连续的工作区。查询工具栏 `flex flex-wrap items-end gap-3`、中性浅底、`rounded-lg p-4`；搜索框、选择器、查询与重置按钮、更多按钮统一 38px 高、底部对齐；每个查询控件上方有简短标题（`text-xs text-gray-500`）。
- 有显式查询按钮的列表区分草稿条件与已提交条件：修改控件只改草稿，不立即请求；点「查询」或在搜索框按回车时一次提交全部草稿并回到第 1 页；查询进行中控件禁用、按钮显示「查询中…」；「重置」恢复写明的默认条件并立即查询第 1 页，草稿已等于默认值时禁用。导出等依赖当前结果集的操作使用已提交条件；导出范围与勾选无关，除非需求文档定义了按勾选导出。
- 搜索框标题为「搜索」，只在有可搜索的业务列时出现；占位文字只列可搜索的列名，用 ` / ` 分隔，按列表从左到右的顺序，沿用完整列标题，不加「请输入」「支持搜索」之类前缀；提交时去掉换行与首尾空格，并提供简短的中文无障碍名称。
- 列表中显示的每个状态列，默认在工具栏有同名的状态筛选，标题与列标题完全一致；状态筛选默认多选，初始与重置值为「全部」（即空集合，不限制），部分选择显示「已选 N 项」。状态列因权限被隐藏且其存在本身敏感时，对应筛选也不出现。
- 依赖型筛选只在父条件选中后出现，隐藏时清空其草稿值；父子条件一起提交、一起校验；只需要按父状态筛选的，不额外展开参数输入。
- 同一页面的多个标签页可以有不同的查询项；被隐藏的查询项不影响当前结果。
- 工具栏操作组是最后一个元素，`ml-auto` 靠右，顺序为「查询」（主按钮）「重置」（描边按钮），其后是辅助或列表级操作；整组不拆行，空间不足时整组换到下一行并保持靠右。低频操作收进与按钮同高的方形省略号按钮，当前用户没有可用的辅助操作时不显示它；更多菜单右对齐触发按钮，选择后、点击外部或按 Escape 时关闭；菜单按权限过滤，每项 16px 图标加稳定的中文动作名。同一业务动作在工具栏、更多菜单、弹窗标题与反馈文案中使用同一个名字。
- 列设置显示与表头相同的中文名，不露出内部字段名或枚举码；身份、状态、操作列可锁定为禁用的已选项。用户没有字段权限时，敏感列及其列设置项都不出现；每页条数与可见列偏好可以按用户、按列表保存。
- 任何查询条件变化、切换角色或数据范围、切换主标签页时清空已勾选的行。

## 4. 操作与图标

- 表格操作列一律「图标 + 中文动作名」，不用纯图标或纯文字；用轻量文字按钮样式（`inline-flex items-center gap-1 text-sm hover:underline`），不用实心按钮，不加粗；多个操作之间 `gap-3`。图标默认 14，紧凑详情抽屉可用 12，页面级按钮可用 16。
- 动作名与图标取自下方动作字典。需要字典里没有的动作时，沿用「图标 + 中文名」与色调规则，在原型的操作配置里登记，并在交付说明里列出新增的动作交用户确认。颜色只表达风险与状态变化，不表达业务类别；同一语义的动作在各处颜色一致。优先用共享的操作按钮组件，不在页面里重复散写同样的图标与色值。
- 颜色语义：`primary`（`text-primary-600 hover:text-primary-700`）用于常规主操作；`success`（`text-green-600 hover:text-green-700`）用于正向状态变化；`warning`（`text-orange-600 hover:text-orange-700`）用于有影响但非破坏的操作；`danger`（`text-red-600 hover:text-red-700`）用于破坏、驳回或异常；`neutral`（`text-gray-500 hover:text-primary-600`）用于次要操作；不可用为 `text-gray-300 cursor-not-allowed`。

- 同义动作名统一：查看、查看详情统一为「详情」；修改统一为「编辑」；版本历史、提交历史、审批历史统一为「历史」；下载模板、下载文件统一为「下载」；导入文件统一为「上传」；提交、提交到外部审批统一为「提交审批」。动作名与状态名分开：动作「驳回」，状态「已驳回」。
- **批量操作**：支持批量的列表把勾选列放在第一列（序号之前），表头全选在部分选中时显示半选。有选中行时，表格上方出现批量操作栏（已选数量 + 批量按钮 + 取消选择）；批量按钮就是行操作按钮的复用，动作名不加「批量」前缀，加边框以独立成按钮。每个批量操作只作用于满足该操作条件的选中行，没有符合条件的行时禁用，完成后提示实际影响的条数；角色不能执行单行操作时，也看不到勾选列与批量栏。
- **流程推进**：本系统负责推进的每个非终止状态，在主列表的行操作里至少有一个按状态开放的前进操作，不能只藏在详情里。等待外部审批的状态由外部回调推进，本系统只提供提交、详情、历史等追溯操作。
- **外部审批**：审批节点属于外部审批系统时，本系统页面用「提交审批」发出审批包，之后用详情、历史、下载、进度、重试、通知做追溯，不渲染「同意」「驳回」；「同意」「驳回」只用于本系统内部完成判断的审批节点。原型里模拟外部回调的控制台只对拥有该外部系统的角色开放；其他角色打开同一记录时只读，看不到回调控制台。

## 5. 反馈提示

- 反馈分类：**页面提示**（页面或流程级状态，放在标题下方）；**字段提示**（校验或帮助，紧贴字段下方）；**操作反馈**（按钮或行操作的即时结果，贴近触发控件）；**成功提示**（提交、新建、保存、发布、启用、归档等完成后，出现在视口中部）；**错误提示**（系统拒绝了用户刚做的操作，位置与时长同成功提示，只是色调不同）；**上下文说明**（业务规则、后果或稳定说明，放在相关内容旁）；**状态徽标**（只表示对象状态，用 Badge）。
- 除状态徽标外，各类反馈统一使用一个圆形描边加感叹号的图标（如 `CircleAlert`），颜色随色调；同一类反馈不混用三角、对勾、铃铛或自定义图标。
- 样式：页面提示与上下文说明 `rounded-lg border px-4 py-3 flex items-start gap-2.5 text-sm`；字段提示 `mt-1.5 flex items-start gap-1.5 text-xs leading-5`；操作反馈 `rounded-md border px-2.5 py-1.5 flex items-start gap-1.5 text-xs leading-5`；成功提示固定在 `left-1/2 top-[38vh]` 并居中平移，宽度随内容、有视口最大宽度保护，浅灰底、浅灰边、深绿文字、`rounded-[14px] px-5 py-3.5 text-sm`；错误提示与成功提示同一容器，只把文字与图标换成红色。
- 色调：成功 `bg-green-50 border-green-200 text-green-700`（图标 `text-green-600`）；警告 `bg-orange-50 border-orange-200 text-orange-700`（图标 `text-orange-600`）；错误 `bg-red-50 border-red-200 text-red-700`（图标 `text-red-600`）；信息 `bg-primary-50` 或 `bg-gray-50`、`text-gray-600`。
- 成功与错误提示都显示 5 秒，时长取自一个共享常量，不在调用处写字面量；页面提示与上下文说明不自动消失，除非界面提供关闭操作。
- 汇总可处理事项的说明要写明计数口径，并与它打开的列表使用同一查询口径；代表用户全部待办时按完整授权范围计算，不受主列表当前筛选影响。信息可见与行内操作可见分开判断：有查看权限即可看到说明，只有同时具备操作权限且有可操作对象时才显示「去处理」一类的操作。多条汇总说明并列时各自独立成块，可重叠的计数要说明会重叠；处理后用同一来源刷新计数与列表，计数为零时隐藏。从汇总说明打开的范围列表逐行重新判断权限与操作范围；「去处理」打开对应的范围列表，不去改主列表的草稿条件。
- 抽屉内适用于整张表单的持续性状态、阻断原因或恢复指引，放在固定标题下方、可滚动内容上方的固定提示区；字段校验仍贴在字段旁，操作反馈仍贴在操作旁；只属于某一节或某一步的说明留在该节，不放进固定提示区。
- 状态层与服务层不弹任何界面反馈；守卫类命令以返回值报错，由页面按上述分类呈现；成功提示只在命令确认成功后触发。
- 需求文档里笼统写的「提示」按上述分类落到正确的通道，不为迁就措辞另造组件。
- 禁止：页面内业务操作使用右上角浮动提示（全局外框通知除外）；在业务页面或状态层调用 `alert`、`confirm`、`prompt`；异步命令完成前就提示成功；字段校验错误远离字段；同一页面混用多种反馈形状、图标、颜色与位置；在页面里手写一次性反馈样式。

## 6. 弹窗、抽屉与行内展开

- **弹窗**：遮罩 `backdrop-blur-sm bg-black/50`；确认与决策类弹窗居中（`fixed inset-0 flex items-center justify-center`）；内容丰富时宽度 `w-[min(960px,calc(100vw-48px))]`、最大高度 `max-h-[80vh]`；以表格为主的内容固定表头与底栏、中间滚动，避免窄而高的表格弹窗。同时有业务摘要与明细表时，桌面端左侧放摘要、警告与后果，右侧放明细，明细在有界区域内滚动。
- **二次确认**：不可撤销或对外的操作用统一的确认弹窗组件确认，不用浏览器原生对话框；破坏性操作用 `danger`，锁定或对外提交用 `warning`，中性确认用 `info`；确认按钮执行异步命令，成功后才给成功反馈。
- **抽屉**：新建、编辑与完整详情用抽屉；固定头部、可滚动主体、固定底栏；全高抽屉渲染在文档级浮层根节点（如 Portal），`fixed inset-0` 占满视口高度，不挂在会被裁切或偏移的页面容器里；关闭按钮 `X`（`text-gray-400 hover:text-gray-600`）。对整个对象都重要的状态放在抽屉标题旁，不单独占一行。
- 详情抽屉内的分组标题用主题文字色 `text-primary-700 text-sm font-bold`，标题本身不带分隔线；每组内容之后用中性分隔线（`border-b border-gray-100 pb-6`），最后一组省略。
- 同一对象的新建、查看、编辑复用同一套抽屉信息结构，模式只改变可编辑性、可见命令与校验。提交类按钮（保存、确认、新建、提交）放在固定底栏右侧，次要按钮在前、主按钮在后；头部只放标题与关闭图标。查看模式完全只读；新建模式只开放创建时允许填写的字段；编辑模式按对象状态与权限锁定字段，并在字段或操作旁说明禁用原因。
- 从列表抽屉进入另一个抽屉时替换而不叠加：关闭列表抽屉、打开目标抽屉，保留来源列表的上下文，目标关闭或完成后刷新并重新打开来源列表。抽屉内的工作列表自己管理勾选状态，不复用主表格的勾选与批量状态，除非需求文档明确定义了一个共用的批量操作。
- **行内展开**：用于下级明细、只读子列表与保持表格上下文的快速核对；展开内容把后续行往下推，视觉上像子行而不是独立页面；统一 `text-[13px]`，浅中性底、细边框、紧凑表格，用「明细」而不是「详情」的语义。
- 用户主动打开新建或编辑弹窗时呈现全新的表单，不残留上次的值、校验错误、冲突提示或进行中标记；只有明确的往返流程才恢复草稿。同一对象的新建与编辑使用同一种容器（都用居中弹窗，或都用抽屉）。

## 7. 交互安全与导航

- 所有可交互元素都有 hover 反馈；不可用的操作设 `disabled` 或 `aria-disabled`，样式 `text-gray-300 cursor-not-allowed` 或统一按钮的禁用样式，并在提示、旁边的操作反馈或可见的禁用原因里说明为什么不可用。
- **冲突前置检查**：操作可能与已有数据冲突（身份重复、正在进行的工作）时，在执行前检测并展示，由用户决定排除冲突项继续或取消；不先执行再在成功提示里报告被跳过的部分。
- **唯一性在创建时把关**：身份类约束在创建时就阻断，不推迟到后续步骤；后续步骤只检查状态类条件，服务层另有并发兜底。
- **往返原则**：入口决定返回点。任何跨页跳转都要能回到来源的列表、标签页与滚动位置，从详情返回不跳到无关的默认页；新建或修改跳转链接时，完整走一遍「进入 → 操作 → 返回」，不留死路，不悄悄跳到无关页面。
- 从来源流程（如新建弹窗）跳到次级页面预览时保留来源状态与草稿；次级页面原有的返回按钮保持指向它的默认页，另在标题上方单独一行、左对齐，提供醒目的流程级「返回」按钮，尺寸与页面主按钮一致，悬停提示「返回原流程」；点击后回到原流程，重新打开之前的弹窗或抽屉并恢复草稿。返回目标按进入时记录的上下文动态决定，不写死。

## 8. 角色与导航

- **角色隔离**：不同角色的核心工作流做成独立页面，不用标签页或开关在一个页面里切换角色视图。原型用全局的角色上下文与顶栏身份切换模拟角色；侧边栏与页面内容随当前角色重新渲染；当前角色无权访问的页面不出现在导航中。
- **菜单来源**：可见导航由当前用户实际具备的页面权限决定，没有可见下级的目录自动隐藏；目录本身不是权限点。具备某个操作权限不等于能访问它所在的页面；不在菜单里的详情页、向导步骤与跳转目标同样做访问校验。渲染菜单不得反过来授予权限。
- **数据范围与功能权限分开**：上级组织能查看下级的数据，不等于能编辑；上级可以查看、审批、汇总下级数据，但不能直接编辑下级的数据；跨组织只继承查看类权限，操作与审核类权限不向上汇集。编辑类操作同时校验权限点与数据所属组织，下级的行可见但只读或只可审批。
- 工作台列表只显示操作者本级的事项；对下级的管理（下发、催办、进度、归档、删除）放在单独的任务管理列表里，跨组织的行只读。
- **权限集中判断**：功能权限矩阵落成一份可执行配置，通过唯一入口判断；页面与服务层不散落写死的角色数组。从旧的授权路径迁移时只保留一个授权来源，新路径拒绝时不回落到旧路径。
- **角色与岗位**：角色是与组织无关的权限主体，岗位是角色落在具体组织上的实例；顶栏身份切换列出岗位，授权按岗位对应的角色判断；增加组织只需增加岗位，不改角色定义与权限矩阵；数据范围的类型来自角色，具体组织来自当前岗位，服务与页面不按角色写死组织 ID。
- **角色切换**：切换角色后先跳到新角色的等价节点；没有等价节点时去同一父菜单下第一个可访问页面，再不行去首页；首页也不可访问时去导航顺序中第一个可访问页面；一个可访问页面都没有时，显示写明联系谁的无权限状态并停下。不循环跳转，不退回到管理员视图，不把用户留在空白页或通用的「无权限」页。切换身份时清掉上一身份可见的列表、已打开的详情、缓存的敏感值与弹窗，上一身份迟到的响应不得写入当前视图；当前角色在刷新页面与前进后退后保持不变，保存值失效时回到默认身份。
- 等价节点的映射写在导航元数据或集中路由表里，不按页面名称相似去推断；跳转时尽量保留当前的周期、组织、任务等上下文。属于外部系统的流程不是本系统的等价页面。
- **侧边栏**：一级菜单 `px-6`，二级 `pl-14`，三级 `pl-[70px]`（三级首字对齐二级第二个字）；一至三级都用 `text-sm`；三级选中项不加粗，只用背景高亮与文字颜色表达；未选中的三级菜单用 `text-gray-500`。没有目标页的二级目录点击时：当前不在它的下级页面且目录原本折叠，才跳到第一个可访问的三级页面，其余情况只切换折叠状态。角色切换时按菜单树逐级向上找同级可访问页面，再退到顶级菜单或首页。

## 9. 文案

- 面向用户的文案、标签、按钮名、状态名一律中文；代码标识与动作键用稳定的英文，配中文显示名。
- 站在业务用户的角度写，不暴露「映射」「1:1」「锁定关系」「实体」「异步」「幂等」这类实现术语；校验与错误文案说明发生了什么、为什么重要、怎么恢复；优先说业务影响，不说实现细节。
- 页面上下文已经确定了归属层级时，列表标题用简洁的对象名，不重复层级前缀；多个层级并列或去掉会产生歧义时保留。
- 领域模型里出现在界面上的实体都要有产品化的显示名，不在页面上出现「批次」「实例」「快照」这类技术名词；内部名称不随显示名改变，二者的对应关系登记在需求文档的术语表里；列表标题、状态、提示与空状态一致使用显示名。
- 状态名描述当前业务阶段或持久结果：「待…」表示排队或未提交，「…中」只用于进行中的过程，「已…」表示完成或终止；不机械地给每个名词加「中」「已」；审批的「通过」「驳回」通常是转移事件，除非业务需要按它查询，否则不单独作为状态；集成阶段承担锁定、补偿或时限跟踪时使用持久的业务状态，技术投递标签只能作补充，不能代替业务状态。
- 需求文档中解耦的两条流程，各自的列表只显示自己口径的状态，不把另一条流程的逐行状态或详情链接嵌进来；跨流程下钻用明确的入口按钮。
- 滚动条样式统一定义在全局样式中，不在页面里重定义。
- 百分比统一保留一位小数，输入占位为 `0.0`，`%` 放在输入框右侧而不是标签里；比例输入校验为正数并在旁边提示。
- 日期：中文格式 `YYYY年MM月DD日`，标准格式 `YYYY-MM-DD`；表格与数据类展示中的月份用 `M01`…`M12`，正文描述保留中文的月份说法。表示时间容器的周期编码与表示目标年度的年份分开使用，不混在同一个下拉或表头里。
- 分页文案：左侧「共计 {total} 条数据，共 {totalPages} 页」，右侧「第 ‹ 1 2 3 › 页」，超过 7 页时用省略号压缩；上一页、下一页为 14 号图标按钮（24px 见方、白底、浅灰边框），用 `Tooltip` 组件提示「上一页」「下一页」，并以同样文字作为按钮的可访问名称（如 `aria-label`）。

## 10. 颜色

- 主色 `primary-600`，按下或激活 `primary-700`，浅背景、弱高亮与选中背景 `primary-50`。主色用于主操作、选中的导航、焦点指示与关键指标强调，不大面积用作装饰。
- 页面背景 `#F5F7FA` 或 `gray-50`；内容面 `bg-white` 或 `gray-50`；主文字 `gray-800`/`gray-900`，次要文字 `gray-500`，辅助、禁用与空状态文字 `gray-400`；边框 `gray-100`/`gray-200`。
- 状态色与第 5 节反馈色调一致：成功绿、警告橙、错误红、进行中蓝（`bg-blue-50 text-blue-700 border-blue-200`，图标 `text-blue-600`）。对象状态优先用 Badge，不在页面里逐个重做状态胶囊。
