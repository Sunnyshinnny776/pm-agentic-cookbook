# expected-points：没有 UI/UX 规则时按默认规则生成

- [ ] **D1** 指出没有拿到项目的 UI/UX 规则，告诉用户将按默认的通用 UI/UX 规则生成、如有自己的规则可以给出位置，然后继续产出页面，不因缺规则而停下等待
- [ ] **D2** 交付说明写明本次使用的是默认 UI/UX 规则（与设计令牌）
- [ ] **D3** 操作列为「图标 + 中文动作名」：`详情` 与 `审核` 都带图标与文字，不用纯图标或纯文字按钮；`审核` 只在「待审核」行可用，其他行隐藏，或置灰并说明不可用的原因；字典里没有的 `审核` 动作在交付说明里列为新增动作；不出现删除操作
- [ ] **D4** 「审核状态」用状态徽标呈现；查询区有同名的「审核状态」筛选，默认「全部」；有显式「查询」「重置」，修改条件不立即请求，提交后回到第 1 页
- [ ] **D5** 审核结果提交走异步命令：提交中按钮禁用并显示进行中文案，成功后才给成功提示；驳回原因为必填并有字段级校验；不使用浏览器原生 `alert` / `confirm`
- [ ] **D6** 列表字段、查询条件与操作按需求文档实现，不增删；列表至少 5 条真实感的模拟数据；只做资质审核员一个角色的业务页面（为演示身份切换而建、不含任何业务功能的其他角色占位页不算越界）

## 判定

- **D1、D2 是核心**：守护的是「缺规则时不停下、但必须说明用的是默认规则」这一条新行为。被试只因缺 UI/UX 规则就停下，D1 判未命中，D3–D6 判「无法判定」。
- D3–D5 检验的是默认规则真的被用上了，判卷时对照被试产出的代码与说明，不要求与默认规则逐字一致。
