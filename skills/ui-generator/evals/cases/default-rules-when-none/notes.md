# notes：没有 UI/UX 规则时按默认规则生成

## 守护什么

`ui-generator` 的输入规则：宿主没有声明 UI/UX 规则、调用方也没给规则时，不停下，先提示用户可按默认的通用 UI/UX 规则生成或给出自己规则的位置；用户没有另外指定，就按 skill 自带的默认规则与设计令牌继续，并在交付说明里写明。同时检验默认规则在产出中确实生效（操作列、状态与查询、异步提交与反馈）。

## 为什么这样设计

需求文档故意写全，排除「因需求缺口停下」的干扰，让停与不停只取决于 UI/UX 规则这一项。场景选供应商资质审核，与 skill 正文和默认规则中的写法都不同源；操作只有「详情」「审核」两个，便于判断动作字典与按状态开放是否生效。

## 怎么跑

1. 仓库外建空目录，`.claude/skills/ui-generator/` 放 skill 源码（排除 `evals/`、`dist/`）；不放 `cookbook.config.json`。
2. `fixtures/prd.md` 复制为 `docs/资质审核需求.md`。
3. 新会话冷启动，原样发送 `input.md` 的「给被试的原话」；不回答追问。
4. 判卷由独立执行者按 `expected-points.md` 逐条勾选。
