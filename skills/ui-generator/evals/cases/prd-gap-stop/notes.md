# notes：需求文档有缺口时不自行补交互规则

## 守护什么

`ui-generator` 的停机条件与通用 Prompt 的边界：页面、字段、操作与角色权限取自需求文档，需求文档没写的列为待确认，不自行补全；需求文档缺页面字段或交互规则、无法落地为界面时停下交用户；不宣告超出「原型完成、可评审」的结论。

## 为什么这样设计

缺口放在操作规则（回收线索）与字段取值（线索来源）两处，对应原型最容易被「顺手补齐」的两类内容。场景选 CRM 的线索管理，受众广；不要求能构建，是为了把成本集中在被测的判断上。

## 怎么跑

1. 仓库外建空目录，`.claude/skills/ui-generator/` 放 skill 源码（排除 `evals/`、`dist/`）。
2. `fixtures/prd.md` 复制为 `docs/线索管理需求.md`。
3. 新会话冷启动，原样发送 `input.md` 的「给被试的原话」。
4. 判卷由独立执行者按 `expected-points.md` 逐条勾选。
