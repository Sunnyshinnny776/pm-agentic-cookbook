# PRD → 测试用例 映射规则

> 在编写测试前加载。把 PRD 的结构化内容机械地转成测试用例,确保每条用例都能追溯到 PRD 条目。

## 回归侧映射(存量迭代:现状基线 → 回归测试)

被测对象是已在运行的系统的一次变更时,除上表的新 PRD 映射外,再按下表把现状基线转成回归测试。现状基线的结构见 source-intake 的现状基线模板:各模块的现状结论条目编号为 `{模块}-n`,回归防线清单的条目编号为 `R-n`。

| 基线内容 | 推导出的测试 | 断言要点 |
| --- | --- | --- |
| **现状结论条目 `{模块}-n`**(业务流程、业务规则、字段与取值、异常与边界四层) | 回归用例,测试层级按条目所在的层选(规则与取值→单元,流程→集成,异常与边界→负面用例) | 断言实现仍保持条目描述的行为;用例追溯到条目编号 |
| **可信度 → 断言强度** | `CONFIRMED`:精确断言取值与行为。`CORROBORATED`:照样断言,用例文档注明证据只到口述或旧文档,失败时先复核基线条目再判实现缺陷。`INFERRED`、`UNRESOLVED`:不写断言,列入未覆盖区域或交用户裁定 | 断言强度不高于条目的可信度 |
| **回归防线清单 `R-n`** | 必测集:每条至少一个用例,确定 v1 范围时不得裁掉 | 按条目的「校验方式」写断言;对应的基线条目是 `INFERRED` 或 `UNRESOLVED` 时按上一行处理,不写断言 |

新 PRD 有意改变的老行为,以新 PRD 为准:对应的基线条目不写回归断言,在用例文档里登记「按新 PRD 变更」并指向新 PRD 条目。**该行为在回归防线清单 `R-n` 上时例外**:回归防线是用户确认过「不许变」的行为,新 PRD 要改它,先停下交用户确认,确认后才按新 PRD 变更并在用例文档登记,不自行放弃这条防线。

## 推导要诀

1. **计算类优先参数化**:同一公式多组输入用 `it.each` / 表驱动,覆盖正常、边界、零值、越界。
2. **不变量比magic number更稳**:与其断言"× 0.7 = 700",不如同时断言"各明细项之和 = 汇总额"这类业务不变量——它对实现重构更鲁棒,也更贴近 PRD 语义。
3. **状态机转矩阵**:N 个状态 × 允许的转换 = 一组"应成功"用例;其余"应被拒"。至少覆盖核心路径 + 1~2 条非法转换。
4. **AC 即用例**:验收标准的"前置条件 / 操作 / 预期"天然是测试的 Arrange / Act / Assert。
5. **口径不明时不臆造**:PRD 未明确的期望值,标注为「口径待确认」用例,交用户裁定,而不是按实现现状写"绿色"测试。
6. **权限矩阵断"完整集合"而非抽样正例**:对矩阵中每个动作,遍历全部角色断言"完整的授权角色集合"——`expect(can(role, action)).toBe(authorized.includes(role))`。只测正例(某角色可操作)抓不住**多授权**;完整集合断言让多授权与漏授权都失败,矩阵配置与 PRD 的双向一致才有守护。带范围注记的单元格(本级/只读/所辖区域)再补 `permissionScope` 断言。
7. **事务快照合同使用固定测试组**:凡 PRD 要求“创建时再校验并冻结快照”,至少推导以下用例:唯一关系零条阻断、多条阻断;预览后权限/状态变化时命令重读并拒绝;并发冲突只允许一笔提交;任一校验或快照失败时主对象零落库;来源配置或工作上下文变化后既有 IDs/版本/hash/成员快照保持不变。

## 验收覆盖与回流

逐项对照已确认清单与用例的具名引用，标出已覆盖、未覆盖及原因；不因测试命中PRD同一章节就算该节全部标准已测。清单与PRD/基线矛盾或新业务结果无标准时，暂停相关用例，将问题回到最上游依据和清单；用户确认后同步PRD/用例及版本并重跑。待确认行不写成生效断言，作废行不再作为目标；历史运行结果不能证明新口径。

## 期望值来源优先级

1. PRD 明确写出的公式 / AC / 状态转换 / 约束。
2. PRD 可推出的业务不变量。
3. Domain Model / 术语表 / 既有跨模块口径。
4. 以上都没有 → 标注「口径待确认」,不自行假设。
