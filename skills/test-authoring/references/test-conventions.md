# 测试用例与命名 / 分层 / 裁定约定

> 在落地可执行测试与产出报告时加载。

## 测试金字塔分层

| 层 | 被测对象 | 技术(示例) | 特征 |
| --- | --- | --- | --- |
| **单元** | 纯函数、派生逻辑、数据契约 | Vitest | 快、确定、无副作用,优先做厚 |
| **集成** | 状态流转、跨实体规则、台账/审批副作用 | Vitest + 状态容器(如 Testing Library `renderHook`) | 验证业务过程,需最小可控环境 |
| **组件** | 关键页面渲染与核心交互 | Vitest + Testing Library + jsdom | 1~2 个即可证明渲染/交互闭环,避免过度铺开 |
| E2E(迭代再加) | 跨页面全流程 | Playwright 等 | v1 不要求 |

## 命名约定

- 测试文件就近:`<被测>.test.ts` / `.test.tsx`;集成测试 `<域>.integration.test.tsx`。
- `describe` 写"被测对象 — 关注点(PRD 章节)";`it` 写"在什么前置下,期望什么"。
- **验收引用**：用例文档、关键测试注释使用清单名称加编号；Oracle版本包含清单路径/版本。清单与PRD冲突时停止并回改，不能用来源优先级自行盖过冲突。
- **追溯标注**:测试文件顶部注释写明追溯的 PRD 文件与章节;关键用例在 `it` 描述或注释内点名 PRD 条目。
- **待裁定用例**:以 PRD 为预言、预期会失败以暴露偏差的用例,`it` 描述加 `[待裁定]` 前缀,并在注释说明"这是有意的发现,非框架故障",注明分类(实现缺陷 / 口径待确认)。

## 失败分类与裁定

每个失败项必须给出:

| 字段 | 内容 |
| --- | --- |
| 分类 | 「实现缺陷」/「PRD/Mock 口径待确认」 |
| 证据 | 期望值(PRD 口径)vs 实际值 |
| 定位 | `文件:行` |
| P 分级 | P0 阻断核心流程/数据正确性;P1 关键规则偏差;P2 口径待确认/边界;P3 优化 |
| 裁定 | 留空,由用户填:修复 / 改 PRD 口径 / 接受并记录 |

**红线**:不得为追求"全绿"把测试改成迁就实现现状;不得在报告里替用户下"通过/可推进"结论。

## Oracle 版本同步

- 测试用例文档必须记录当前 PRD / Domain Model 的基线版本或日期。
- Oracle 变更影响实体、业务不变量、状态机、权限、集成契约或验收标准时,同一批次更新对应追溯与预期。
- 旧 Oracle 下的“通过”状态不能沿用到新预期;在可执行测试完成前标为“待更新”或“待实现”。
- 设计层可以先登记待实现用例,但没有机器结果或走查证据时不得标记为已执行通过。
- 测试报告记录真实执行历史,不随 PRD 审计报告更新而自动删除或改写。

## 测试隔离陷阱

- **模块级单例内存缓存**:被测代码若在模块加载时创建带内存状态的单例(如缓存持久化快照的 service),即使测试环境按用例清理 storage,单例缓存也不会复位,状态会跨用例泄漏,且失败呈"远处用例莫名挂掉"的形态难定位。对策:mock 持久化实现按**无状态仓储**写(storage 即唯一事实源,每次访问现读),或为单例提供显式 reset 钩子并在 setup 中调用。
- **异步契约下的 act**:被测状态层为 async 命令时,`act(() => …)` 不冲刷微任务,断言会读到旧状态;一律 `await act(async () => …)`,循环内 `forEach` 换 `for…of` 以合法使用 `await`。

## 反向验证(守卫类用例的证伪力)

新增的守卫类用例(阻断、置灰、权限、隔离、门禁)必须做**反向验证**:临时退回被守护的实现,确认用例变红,再恢复。未经反向验证的守卫用例可能自始至终不具证伪力——它测的是"当前实现的行为",不是"规则被违反时会被发现"。

判定有效的两条硬标准:

- **红得是地方**:失败原因必须是**断言失败**。因编译错误、类型错误、渲染崩溃而红的**不算数**——那证明的是"代码被改坏了",不是"用例守住了规则"。回退成对结构(JSX 开闭标签、成对配置项、前后置钩子)时必须**成对回退**,否则产物根本编译不过。
- **复现真实机制**:用例构造的场景必须与缺陷的真实触发机制一致。若缺陷发生在**运行中的状态变化**(组件挂载期间切换角色、计算窗口内发起写操作),用例不得用"重新挂载 / 重新初始化"替代——重新挂载会绕开缺陷路径,退回实现也不变红。同理,数据隔离类用例必须备好**跨边界且会真正相撞**的种子(如同一员工在两个组织各有一条待处理记录),否则过滤逻辑被删也测不出来。

反向验证的结论要写进测试报告:哪些守卫验过、哪些首次验证不成立及如何修正。(例:某越权用例首版用重新挂载,退回实现后仍不变红;某标签嵌套用例首版只回退开标签,得到的是 JSX 编译失败而非断言失败;两者都要重做)
