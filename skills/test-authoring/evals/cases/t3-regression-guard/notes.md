# notes：T3 存量迭代的回归防线

## 守护什么

`test-authoring` 规定：**迭代场景下 oracle 是两份，不是一份**——现状基线 + 新需求文档，老行为不许变。

这是 `source-intake` 的现状基线与 `test-authoring` 之间的接缝。基线由准入一侧产出，测试由另一侧编写，本 case 检验两侧接不接得上。

## 为什么材料里要塞一条 INFERRED

`source-intake` 的现状基线模板规定 `INFERRED` 条目不得进入回归防线：用一条推断去卡住变更，会把猜错的现状固化成需求。这条规则写在准入一侧，本 case 检验测试一侧是否也按可信度标签区别对待。

把第 3 条老行为标成 `INFERRED`，就是在测这个接缝。
