# 审计动作与报告元信息

> Supporting reference for `check-prd`. Every audit loads this reference. 它只规定本 skill 作为审计者做什么。变更等级（M0/M1/M2）、修复批次、问题登记与原文清理由派发方执行，不在本文件。

## 1. 三种审计动作在本 skill 下的范围

派发方会声明本次是哪一种动作。

| 动作 | 本 skill 下检查什么 |
| --- | --- |
| **独立审计（initial audit）** | 产品定型、全部适用维度、重大风险项；加载了领域 Provider 时加上领域专项 |
| **定向复审（focused recheck）** | 逐项核销派发方给出的**全部未关闭条目**；没有旧条目时，验证派发列出的 local change target、预期语义与验证边界。两种情况都检查受影响维度与邻接回归，不得只看作者摘要 |
| **完整重审（full re-audit）** | 与独立审计相同的全部范围，从当前文件冷启动，不采信上一轮报告的结论 |

**复审与重审先冻结判定，再看旧条目。** 先按当前文件完成判定并写入报告，之后才读派发方给出的旧条目做核销。先看旧结论会被它牵着走，只去验证旧问题，漏掉新问题。

本 skill 只回答"这份需求文档本身写得好不好"。需求文档与模型、代码、图示、测试规格之间是否一致，不在本 skill 的标准里；发现这类线索时记为"建议一致性审计复核"，不代为判定。

## 2. 审计者边界

- 对被审产物始终只读：不得修改需求文档、模型、规范、源码或测试。
- 只写本次报告；不修改问题登记表，不删除、不标记任何其它文件。
- 新发现使用独立编号，进入"新增发现"章节。
- 同一份报告分多次写入时，只追加自己的顶层章节，不修改既有章节。
- 不宣告"通过 / 可推进"；是否修复、是否再审由用户决定。

## 3. 报告必须包含的元信息

| 项 | 内容 |
| --- | --- |
| 被审对象 | 逐个文件路径与版本或 hash |
| Oracle | 判定所依据的文件路径 |
| 审计快照 | 提交 hash 或文件 hash；工作区是否干净 |
| 审计动作 | initial / focused / full，以及派发方给出的变更等级 |
| 输出时间 | 日期与时间 |
| 本轮未读清单 | 与本次审计相关、但本轮没有读的文件或对象类，以及原因。没有时写"无" |
| 条目核销表 | 派发方给出的全部未关闭条目：编号、当前状态（已修 / 部分修 / 未修 / 不再适用）、证据。首次审计写"首轮，无旧条目" |

每条发现写到**不回看报告正文也能判断**的程度：现象与后果、位置（文件与行号）、复现方式或判据。派发方会据此把它登记进问题登记表，报告原文之后会删除。

## 4. 单独使用时

没有派发方、由用户直接调用本 skill 时，报告在对话里逐维度交付，写完即结束；报告就是交付物，是否保存、保存在哪由用户决定（用户要保存而没有指定位置时，按 `SKILL.md` 输入一节的默认位置）。
