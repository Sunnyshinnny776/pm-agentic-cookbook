# HR 系统领域专项审查

> 当 PRD 涉及 HRM、HCM、组织人事、薪酬、算薪、个税、社保公积金、考勤、绩效、招聘、员工服务、人力预算或审批协同时加载本附录。

## 适用原则

本附录增强原有 14 维检查框架，不替代原框架。审查时仍以《决胜B端》《决胜体验设计》和 PRD 模板为基础，同时叠加 HR 系统领域的业务约束。

HR 系统不等同于企业自研系统。它可能是商业化 SaaS、企业自研系统、私有化交付项目或二开项目。审查时必须同时判断：

| 维度 | 可选值 | 审查影响 |
| --- | --- | --- |
| 商业属性 | 商业化 / 自研 / 私有化 / 二开 | 决定商业分析、多租户、配置化、实施交付和运营检查侧重 |
| 功能类型 | 业务型 / 工具型 / 交易型 / 基础服务型 | 决定 ER、流程、权限、API 等检查深度 |
| HR 子域 | 组织人事 / 薪酬 / 算薪 / 个税 / 社保公积金 / 考勤 / 绩效 / 预算 / 审批 / 员工服务 | 决定实体、状态、时间口径、敏感数据和上下游关系 |
| 文档粒度 | 系统级 / Overview PRD / 模块级 / 子功能级 / 迭代级 | 决定是否要求完整 ER、完整架构、完整商业章节、上位边界或只审本功能边界 |

## 前置材料一致性检查

审查 HR 领域 PRD 时，除阅读 PRD 本身外，应检查它是否引用并对齐已有材料：

| 材料类型 | 检查重点 |
| --- | --- |
| 解决方案或源材料 | PRD 的业务规则是否有依据；是否引入无来源的行业假设 |
| Domain Model / 数据模型 | 实体、字段、状态、关系、读写边界是否一致 |
| 相邻模块 PRD | 与组织、人事、考勤、薪酬、预算、OA、财务、个税等模块是否有冲突 |
| 权限或组织规则 | 角色、组织树、责任范围、平级隔离、租户隔离是否一致 |
| UI/UX 规范或原型 | 页面结构、表格、操作入口、角色视图是否一致 |
| 接口或集成文档 | 外部系统、同步方式、回调、重试、幂等是否一致 |

若 PRD 缺少对前置材料的引用，或与既有材料冲突，应至少标为 P1；若导致核心流程或数据链路不可成立，应标为 P0。

## HR 领域重大风险项

以下风险项应在最终重大风险清单中单独列出，逐条按报告模板的判定档位给出判定：

| 编号 | 风险项 | 触发条件 | 建议级别 |
| --- | --- | --- | --- |
| HR-R1 | 组织数据越权 | 未说明组织树、责任范围、平级隔离、集团/租户边界，或不同角色可见数据范围不清 | P0/P1 |
| HR-R2 | 人员粒度混淆 | 混用员工、账号、任职、岗位分配、薪资档案、发薪人员等粒度，导致数据关系不成立 | P0/P1 |
| HR-R3 | 时间口径混乱 | 混淆自然月、薪资月、考勤周期、社保月、预算月、税款所属期、审批时间 | P0/P1 |
| HR-R4 | 敏感数据无保护 | 薪资、个税、证件号、银行卡、社保、公积金、绩效结果等缺少权限、脱敏、加密或导出控制 | P0/P1 |
| HR-R5 | 状态锁定缺失 | 审批中、已生效、已锁定、已归档、已发放等状态仍允许无约束修改 | P0/P1 |
| HR-R6 | 导入同步不可追溯 | 批量导入、外部同步、审批回写、计算重跑缺少版本、明细、幂等和失败处理 | P1 |
| HR-R7 | 跨模块数据流断裂 | 上游数据来源、下游消费方、异常回写或状态联动未定义，导致流程无法闭环 | P0/P1 |
| HR-R8 | 审计追溯不足 | 关键操作缺少操作人、时间、来源、前后值、审批记录、文件或异常处理记录 | P1 |
| HR-R9 | 数据权限与功能权限混淆 | 仅按"可见数据范围"定义权限，未区分数据查看权与功能编辑/操作权；把"上级可见下级数据"直接等同于"上级可编辑下级数据"。**继承链判据**：同一组织内（组织协管员→组织管理员）全类继承；**跨组织只继承查看类，操作类与审核类一律不上卷**——审核通常是组织内部动作（提交至本部门负责人、驳回退回本部门经办人），跨组织的把关走审批流或外部 OA，是另一个节点。上级角色的操作/审核权来自它自己的本级，不是从下级继承而来 | P0/P1 |
| HR-R10 | 派生金额不变量被破坏 | PRD 允许在明细层之外单点改写"由明细逐行派生的汇总金额"（预算批复额、工资汇总、计提额等）——典型如为审批环节设计"核减/调整后通过"。这会破坏「明细加总 = 汇总额」不变量，且后果显现在依赖该派生关系的另一个模块（如执行监控层按明细派生科目额度），单模块审查极易漏判。数据修改只能发生在明细层、由数据所有方执行后重新派生 | P0/P1 |
| HR-R11 | 敏感字段与导出随范围继承 | 把"上级可见下级记录"直接推成"上级可见下级的薪资金额/证件号/银行卡"，或导出权随查看权一并下发。二者应**独立授权**：敏感字段查看须单独开通并留痕，导出须单独开通并附二次确认、水印/加密、操作人与行数审计。行列权限分离是生产系统通行做法；把"不让某层看某类数据"实现成组织范围屏蔽，会连它本该看的记录一起挡掉 | P0/P1 |
| HR-R12 | 全局配置动作被当作组织数据求值 | 全局字典、标准模板、周期定义、任务下发、集团方案这类动作，其对象是**全局主数据与流程配置**，不属于任何单一组织。若把它们叠加组织范围判定，会导致集团层角色连本职管控动作都无法执行；反之若不加区分地放行，又会让上级组织不得代办下级组织操作的约束形同虚设。PRD 应能对每个权限点判定它是否按组织求值 | P1 |
| HR-R13 | 角色体系在模块 PRD 内被重造 | 项目已有统一角色来源（角色元数据、系统级角色权限登记表、上位模块 PRD）时，模块 PRD 仍自行罗列角色定义、数据范围甚至另造角色名。后果是角色定义出现多处出处并各自漂移；也常见把组织层级写进角色名（"分公司管理员"），使同一档治理权限在不同层级重复造角色 | P1 |

### 风险项详解

速查表给触发条件与级别，本节给判断标准、为什么重要与改进建议——**报告里要写清"为什么这是风险"时用这一节**。

#### HR-R1 组织数据越权

- **适用范围**：涉及 HR 系统领域时适用
- **触发条件**：PRD 未定义组织树、责任范围、平级隔离、集团/租户边界，或敏感数据在不同组织间可越权查看
- **判断标准**：无法判断某角色能看到哪些员工、组织、薪资、个税、考勤或预算数据
- **为什么重要**：HR 数据通常涉及个人信息和薪酬隐私，越权查看会造成严重安全和管理风险
- **改进建议**：补充组织数据权限矩阵，区分本人、本部门、本组织、下级组织、责任范围、集团全局和租户范围
- **参考依据**：本附录 + RBAC 数据权限模型

#### HR-R2 人员粒度混淆

- **适用范围**：涉及 HR 系统领域时适用
- **触发条件**：PRD 混用员工、账号、任职、岗位分配、薪资档案、发薪人员、业务期间等概念
- **判断标准**：多任职、调岗、兼职、多薪资档案、历史追溯等场景下数据关系不成立
- **为什么重要**：HR 系统实体粒度错误会直接导致流程、权限、计算和历史数据错误
- **改进建议**：对齐 Domain Model，补充实体定义、外键关系、时间口径和状态机
- **参考依据**：本附录 + ER 建模方法

#### HR-R4 敏感数据无保护

- **适用范围**：涉及薪资、个税、证件号、银行卡、社保、公积金、绩效等敏感数据时适用
- **触发条件**：PRD 未说明脱敏、加密、导出控制、访问审计或字段级权限
- **判断标准**：普通页面权限即可查看或导出完整敏感数据
- **为什么重要**：敏感数据泄露会造成合规、劳动关系和企业管理风险
- **改进建议**：补充敏感字段清单、脱敏规则、导出权限、审计日志和异常处理
- **参考依据**：B 端数据安全 + 本附录

> 与 `HR-R11` 配合看：本项判"有没有保护"，`HR-R11` 判"保护有没有随组织范围被稀释"。

#### HR-R6 导入同步不可追溯

- **适用范围**：涉及批量导入、外部同步、审批回写、薪酬/个税/绩效/预算计算时适用
- **触发条件**：PRD 未设计版本、行级明细、校验结果、幂等键、失败重试、计算快照或锁定态保护
- **判断标准**：重导、重算、重复回调或同步失败后无法追溯，也无法恢复到一致状态
- **为什么重要**：HR 数据通常进入薪资、个税、预算、审批等关键链路，不可追溯会破坏结果可信度
- **改进建议**：补充数据集版本、行级校验、异常明细、幂等、重试、快照和审计规则
- **参考依据**：本附录 + 异常处理与数据治理要求

## 维度专项检查项

**加载本 Provider 时，在对应维度的通用检查之外追加执行。** 上方「维度映射」表说的是"哪个维度要关注什么"，本节给的是可勾选的检查项本体。


### 维度02 产品类型适配性

- [ ] **HR 子域识别**
  - 检查内容：PRD 是否明确属于哪个 HR 子域，或是否跨多个 HR 子域。
  - 优质标准：明确写出 HR 子域，例如组织人事、薪酬、算薪、个税、社保公积金、考勤、绩效、预算、审批、员工服务，并说明上下游模块。
  - 问题标志：只写“HR 系统”或“人力资源模块”，但无法判断实际业务范围。
  - 参考依据：HR 系统领域专项审查。

- [ ] **HR 交付形态适配**
  - 检查内容：PRD 是否区分 HR SaaS、企业自研、私有化交付、二开项目的差异。
  - 优质标准：SaaS 强化多租户、配置化和标准化；自研强化内部流程和组织权限；私有化/二开强化实施配置、接口适配和升级兼容。
  - 问题标志：HR SaaS 没有租户隔离；自研系统写大量无关的获客指标；二开项目不说明与既有系统的兼容边界。
  - 参考依据：《决胜B端》产品部署模式与产品化策略。


### 维度07 数据建模

- [ ] **人员与组织粒度**
  - 检查内容：是否区分员工、账号、任职、岗位、岗位分配、组织、部门、薪资档案等不同实体。
  - 优质标准：调岗、兼职、多任职、组织变更、历史追溯场景下，数据关系仍然成立。
  - 问题标志：用 `employee_id` 承载所有业务关系，无法表达多任职、多薪资档案或历史组织。
  - 参考依据：HR 系统领域专项审查。

- [ ] **时间口径实体化**
  - 检查内容：是否明确薪资月、自然月、考勤周期、社保月、预算月、税款所属期等时间口径及映射关系。
  - 优质标准：关键时间口径有实体或字段承载，并说明读取、锁定和归档规则。
  - 问题标志：PRD 中多处使用“当月”“本期”但没有定义业务含义。
  - 参考依据：HR 系统领域专项审查。

- [ ] **敏感数据字段**
  - 检查内容：薪资、个税、证件号、银行卡、社保、公积金、绩效结果等字段是否标注敏感级别和保护方式。
  - 优质标准：说明脱敏展示、加密存储、导出权限、访问审计和日志处理。
  - 问题标志：敏感字段按普通字段展示或导出，无权限和审计说明。
  - 参考依据：B 端数据安全与 HR 领域专项审查。

- [ ] **导入同步与版本明细**
  - 检查内容：批量导入、外部同步、审批回写、计算重跑是否保留数据集版本、行级明细、来源文件、校验结果和幂等键。
  - 优质标准：重导不覆盖历史证据，重复回调不产生重复业务结果。
  - 问题标志：只写“导入成功后覆盖原数据”，没有版本、明细和异常修正路径。
  - 参考依据：HR 系统领域专项审查。


### 维度08 流程与角色权限

- [ ] **组织数据权限**
  - 检查内容：是否说明本人、本部门、本组织、下级组织、责任范围、集团全局、租户范围之间的差异。
  - 优质标准：角色权限矩阵同时包含功能权限和数据范围；平级组织不可见；集团角色上看下；SaaS 场景租户隔离。
  - 问题标志：只写“管理员可查看全部”，但没有组织树和责任范围规则。
  - 参考依据：HR 系统领域专项审查。

- [ ] **状态锁定流程**
  - 检查内容：审批中、已生效、已锁定、已归档、已发放等状态下是否禁止或限制修改。
  - 优质标准：每个锁定态有清晰的可见、可编辑、可撤回、可解锁和审计规则。
  - 问题标志：已提交审批或已生成结果的数据仍允许直接编辑。
  - 参考依据：状态机和 RBAC 权限模型。

- [ ] **跨模块协同流程**
  - 检查内容：是否说明与组织、人事、考勤、薪酬、预算、OA、财务、个税等模块的入口、回写、异常流。
  - 优质标准：上游数据变更、同步失败、审批回调、下游消费都有状态和处理方案。
  - 问题标志：只写“从考勤同步”“推送 OA”，但没有失败、重复、撤回、状态回写规则。
  - 参考依据：HR 系统领域专项审查。

- [ ] **敏感操作权限**
  - 检查内容：是否单独定义薪资、个税、银行卡、证件号、社保、公积金、绩效等敏感数据的查看、导出、编辑、审批权限。
  - 优质标准：敏感字段权限细到页面元素或字段级，导出和批量操作有更高权限和审计。
  - 问题标志：有页面权限即默认可查看全部敏感字段。
  - 参考依据：B 端数据权限与 HR 领域专项审查。


### 维度09 交互设计

- [ ] **批量导入/同步交互**
  - 检查内容：是否说明模板下载、文件上传、解析进度、校验结果、失败明细、修正后重导、历史版本查看。
  - 优质标准：大批量操作有进度、可取消/重试、失败明细可导出，重导不会覆盖历史证据。
  - 问题标志：只写“支持 Excel 导入”，没有校验反馈和异常修正路径。

- [ ] **异常处理入口**
  - 检查内容：人员变动、未定薪、数据缺失、权限不足、负值/超限、外部同步失败等异常是否有统一或局部处理入口。
  - 优质标准：异常可定位到人员/档案/数据行，能跳转处理，处理后状态可追踪。
  - 问题标志：异常只用 Toast 提示，用户无法回到问题行或下载修正数据。

- [ ] **敏感字段展示**
  - 检查内容：薪资、个税、证件号、银行卡、社保、公积金、绩效等敏感字段是否设计脱敏、查看授权、导出限制。
  - 优质标准：列表默认脱敏，详情或导出需权限，敏感查看有审计。
  - 问题标志：薪资或证件号在列表中明文展示，导出权限与查看权限不区分。

- [ ] **锁定态与只读态**
  - 检查内容：审批中、已生效、已锁定、已归档、已发放等状态下，页面是否明确禁用编辑、导入、删除、重算等操作。
  - 优质标准：按钮置灰说明原因，必要时提供解锁/撤回入口并记录审计。
  - 问题标志：PRD 未说明锁定态页面表现，研发无法判断按钮可用性。

- [ ] **跨模块跳转**
  - 检查内容：从 HR 模块跳转到组织、人事、考勤、社保、个税、预算、OA、财务等模块时，是否保留上下文和返回路径。
  - 优质标准：跳转携带人员、期间、组织、异常类型等上下文，返回后可继续原流程。
  - 问题标志：只写“跳转处理”，没有说明跳转目标、参数和返回后状态。


### 维度12 异常处理

- [ ] **导入/同步异常**
  - 检查内容：是否覆盖模板错误、文件格式错误、行级校验失败、重复数据、未匹配人员、外部系统不可用、部分成功等场景。
  - 优质标准：异常可定位到文件、行号、人员、实体和字段；支持下载失败明细、修正后重导、保留历史版本。
  - 问题标志：只写“导入失败请重试”，没有失败原因、明细和恢复路径。

- [ ] **审批与锁定异常**
  - 检查内容：是否覆盖审批撤回、驳回、超时、审批人离职、重复回调、业务对象已锁定等场景。
  - 优质标准：审批状态与业务对象状态一致，重复回调幂等，锁定态修改需要解锁或撤回流程。
  - 问题标志：OA 回调失败或重复回调时，PRD 没有说明业务状态如何处理。

- [ ] **计算和重算异常**
  - 检查内容：薪酬、个税、绩效、预算等计算类模块是否说明缺失输入、规则冲突、负值/超限、重复计算、重算覆盖策略。
  - 优质标准：计算输入有版本和快照，重算可追溯，异常不覆盖已审核或已锁定结果。
  - 问题标志：允许用户修改输入后直接覆盖历史结果，无版本和审计。

- [ ] **敏感数据安全异常**
  - 检查内容：是否覆盖越权查看、导出泄露、日志记录敏感明文、附件泄露、离职人员权限未回收等场景。
  - 优质标准：敏感操作有权限、脱敏、审批或审计；日志和导出文件不暴露明文敏感数据。
  - 问题标志：导出、日志、异常明细中包含完整证件号、银行卡号、薪资或个税明细。

## HR 领域实体粒度专项

根据 PRD 子域选择适用实体，并检查是否混淆：

| 子域 | 常见实体 | 常见错误 |
| --- | --- | --- |
| 组织人事 | Employee、Organization、Department、Position、PositionAssignment、EmploymentStatus | 把员工等同于任职；调岗后历史组织被覆盖 |
| 薪酬/算薪 | SalaryProfile、SalaryItem、PayrollRule、PayrollPeriod、PayrollBatch、PayrollResult | 把员工粒度当作薪资档案粒度；薪资月与自然月混用 |
| 定调薪 | SalaryAdjustment、SalaryGrade、SalaryGradeStandard、ApprovalRecord | 生效区间重叠；缺少回溯和未来生效处理 |
| 考勤 | AttendancePeriod、AttendanceRecord、LeaveRecord、OvertimeRecord | 考勤周期与薪资期间关系不清；异常考勤无处理入口 |
| 社保公积金 | SocialSecurityAccount、HousingFundAccount、ContributionBase、ContributionRecord | 缴纳月、基数月、薪资月混淆 |
| 个税 | TaxProfile、TaxRateTable、TaxAccumulator、SpecialDeduction | 税率表版本、累计值、专项附加扣除来源不清 |
| 人力成本预算 | CostBudget、BudgetLine、BudgetPeriod、BudgetVersion | 预算月与薪资月映射不清；预算预警阻断/非阻断边界不清 |
| 审批 | ApprovalInstance、ApprovalNode、ApprovalAction、ApprovalCallback | 审批状态与业务对象状态不一致；回调重复产生重复结果 |

## 模块级 PRD 审查规则

HR 领域 Overview PRD 应先遵循通用 Overview PRD 审查规则，再叠加 HR 专项检查。不要把 Overview 审查写成某个 HR 子域的页面级详细审查；重点检查 HR 子域边界、组织与人员粒度、时间口径、敏感数据、跨模块流向、状态/权限/审计基线，以及后续 Sub PRD 是否被清晰约束。

功能模块级或子功能级 PRD 不一定需要重写完整系统架构和完整 ER，但必须具备：

- 上级模块或 Overview PRD 的引用。
- 本功能涉及实体表：实体来源、读写动作、关键字段、关键状态。
- 本功能数据流：上游来源、本功能处理、下游消费、一致性约束。
- 页面级需求：入口条件、列表/表单/弹窗/抽屉字段、按钮、权限、空态、异常态、锁定态。
- 业务规则：事实、约束、触发条件、推论、计算。
- 验收标准：正常流、异常流、权限流、锁定态、幂等流。

缺少以上内容时，不应因为 PRD 不是系统级文档而放宽到“合格”。
