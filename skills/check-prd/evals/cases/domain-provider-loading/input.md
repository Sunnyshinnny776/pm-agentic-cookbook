## 给执行者的说明

**两问一组，必须都跑，且必须是两个独立的冷启动实例**——同一个实例跑两遍，第二轮的 Provider 加载在上下文里是免费的，测不出冷启动会不会自己去找。

两句话除领域指定外逐字相同。**产出必须不同**——若相同，说明契约在某一侧失效。

被审文档是 `fixtures/sample-prd.md`——**合成语料，非真实项目产出**，刻意留了缺陷（fixture 本身不写这句，避免被试知道自己在应考）。用合成件，是为了让 eval 语料不依赖任何具体项目的内容，可以随 skill 分发。

这份 PRD 里埋了两类缺陷，正好用来区分两轮：

| 类型 | 埋在哪 | 谁该抓到 |
| --- | --- | --- |
| **通用** | 同步失败只说"提示重试"无恢复路径；导入"覆盖原数据"无版本与明细；角色只有两行无数据范围；档案里的敏感字段无任何保护说明；锁定态只约束名单不约束档案数据 | 两轮都该抓（后两条通用层的异常、交互、流程维度本来就覆盖） |
| **领域专属** | 人员粒度未区分（员工/任职/档案混作一谈）；期间与自然月的口径未定义 | **只有指定领域的那一轮该抓** |

若两轮产出相同，说明契约在某一侧失效。

**环境必须干净**：不在宿主项目的仓库里派发——版本库状态会带出分支名与文件名，项目规则文件可能描述不指定领域的后果，两者都是答案线索。被审文件先复制到不含 case 名的中性路径。两轮的派发包装除领域指定外逐字相同，追问也要对称。
