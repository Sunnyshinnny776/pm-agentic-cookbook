# notes：保存需求审查报告

## 守护什么

文件交付路径中每个维度先落盘、后加载下一维度的行为，以及全局前提和最后汇总的执行边界。

## 为什么这样设计

使用已有合成的HR 业务模块 PRD，业务输入与领域加载用例保持一致；本例独立观察保存报告的去向与事件顺序，不增加“请严格逐维度追加”的题外提示。仅看报告最终有14个标题，无法证明按顺序阅读或增量保存。

## 怎么跑

1. 冻结输入和判据，安装当前 skill 及 hrm Provider 到仓库外中性目录，不复制 evals/dist。
2. 新冷启动执行者只收到给被试的原话；保留实际文件写入命令、标准读取事件与全部输出，不给判据或既有审计结论。
3. 独立冷启动判卷者依次核13个相邻维度边界、第一次写入前的准备以及最终汇总位置，保留原始结论。
4. 本例是文件输出路径。若没有真实交互 UI 运行，报告这一证据缺口，不把非交互命令行的分批输出写成 UI 分支已验证。
