# notes：业务事实没说清时是否标出而不补全

## 守护什么

`domain-modeling` 的停机条件与自检：实体、关系、计算链路与业务规则都能追溯到输入材料，推断得来的明确标出；缺少判断实体边界所必需的业务事实时停下交用户；不宣告「模型已定稿」。另守护时态事实的分层建模（审批或调整单与实际生效值分层）。

## 为什么这样设计

三处缺口各对应一种失效：边界（促销覆盖哪些门店）、规则（会员价与促销价）、时态（促销价与常规价）。纪要把前两处写成「没有结论」，是为了让「自行定案」成为可判的错误，而不是口味问题。场景选快消门店的商品价格，受众广，也避开 skill 正文与参考文件里的示例业务。

## 怎么跑

1. 仓库外建空目录，`.claude/skills/domain-modeling/` 放 skill 源码（排除 `evals/`、`dist/`）。
2. `fixtures/minutes.md` 复制为 `docs/商品价格讨论纪要.md`。
3. 新会话冷启动，原样发送 `input.md` 的「给被试的原话」。
4. 判卷由独立执行者按 `expected-points.md` 逐条勾选。
