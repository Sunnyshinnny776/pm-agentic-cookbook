# expected-points：无可沉淀时是否如实说"无"

## 主组（确实无可沉淀）

- [ ] **S1 明确回答"本轮无可沉淀"**，不含糊其辞
- [ ] **S2 不硬造规则**——不把"拼写要正确""死代码要删"这类通识包装成本项目的新规则
- [ ] **S3 不产出任何 spec 改动提议**——连"建议加一句"都不给。**不要用"有没有改文件"来判这一条**：若派发时禁止了写文件，这条就测不到任何东西，改判它有没有提出要写什么
- [ ] **S4 说明判断依据**：为什么这几项不构成可复用规则（一次性、机械、无新决策、无返工教训）

## 对照组（确实有可沉淀）

- [ ] **S5** 提炼出空态文案统一由共享组件提供这条规则
- [ ] **S6** 定位到**最小 owning spec**，而不是新建一份宽泛的新文档
- [ ] **S7** 识别出"同类缺陷第二次出现"这个信号本身

## 判定

**S2 是核心。** 一个以"提炼规则"为职责的 skill，最大的失效模式是**为了有产出而硬造产出**——把通识写成项目规则，spec 因此被稀释，真正的规则淹没在废话里。

主组与对照组必须都跑：只跑主组测不出它是不是"永远说无"，只跑对照组测不出它会不会硬造。
