# 规则归属路由图

> 决定每条可沉淀规则该落到哪里。核心边界:**spec 记可复用规则;PRD 记模块业务;cookbook 记跨项目方法论;代码注释记本地技术细节。**
>
> 宿主的 spec 放在哪里,由宿主契约(宿主根目录 `cookbook.config.json` 的 `host` 一节)声明。本表只给「规则类别 → spec 角色」,具体文件经 `host.specMap` 解析。

## 解析方法

1. 按下表找到规则类别对应的**角色**。
2. 读取宿主契约 `host.specMap` 中该角色登记的路径。**未声明该字段或该角色时,停下请用户指明归属**,不猜路径。
3. 角色登记的是目录时,读其下全部 spec 文件,按文件名与标题选出主题对应的那一份;没有对应文件时,按沉淀例程第 5 步「无既有归属」处理。

## 路由总表

| 规则性质 | 归属 | 说明 |
| --- | --- | --- |
| 角色隔离 / 导航 | `ui-ux` 角色中的角色导航细则 | 角色可见性、动态切换、菜单 |
| 色彩 / 状态 token | `ui-ux` 角色中的色彩细则 | 品牌色、状态色、徽标 |
| 共享组件用法 | `ui-ux` 角色中的组件用法细则 | 按钮、徽标、卡片、表格、分页、提示等复用 |
| 布局 / 弹窗 / 抽屉 / 交互 | `ui-ux` 角色中的布局交互细则 | 栅格、模态、抽屉、提示气泡 |
| 反馈消息 / toast | `ui-ux` 角色中的反馈消息细则 | 反馈分类与图标 |
| 行操作 / 表格操作 / 图标 | `ui-ux` 角色中的操作图标细则 | 图标加动作名、行操作列 |
| 列表查询 / 筛选 / 排序 | `ui-ux` 角色中的列表查询细则 | 查询区、筛选条件、默认排序、空结果 |
| 文档内图示 | `ui-ux` 角色中的图示细则 | 需求文档里流程图、状态图的画法 |
| UX 写作 / 语义兼容 / 命名 | `ui-ux` 角色中的 UX 写作细则 | 中文展示名 + 英文 code key、百分比/日期格式 |
| UI/UX 总纲级约定 | `ui-ux` 角色中的总纲 | 跨细则的约定;高冲突,先确认 |
| 外部系统 / 回调 / 重试 / 状态映射 | `integration` 角色 | 集成全局规则与专项 |
| 测试约定 | `testing` 角色 | 分层、命名、产物、裁定 |
| 前端工程约定 | `engineering` 角色 | 目录结构、数据流、日期区间等实现约定 |
| 安全与权限实现约定 | `security` 角色 | 鉴权、数据可见性的实现规则 |
| spec 加载与沉淀流程本身 | `loading-rule` 角色 | 何时加载哪些 spec、何时做沉淀检查 |
| 模块业务规则(模块专属) | `host.moduleDocs` 下该模块的需求文档;未声明时停下请用户指明 | 仅当是该模块的业务需求,而非可复用规则 |
| 通用方法论 / 流程门禁 | 本 skill 所在 cookbook 的 `<cookbook>/process/` | 阶段流程、门禁 |
| 可复用的 AI 指令规则 | 对应 skill 的 `SKILL.md` / `references/` | 改后须重建该 skill 的 `dist/`(若有) |
| 可复用模板 | 对应 skill 的 `<skill>/templates/`,或 `<cookbook>/templates/` | 需求文档、测试用例、报告等模板 |
| Agent 协作 / 分支治理规则 | `host.rulebooks` 中对应的规则文件;未声明时停下请用户指明 | 高冲突;先确认;每份规则文件归它所管的 agent,改动按宿主约定交由对方或用户应用 |

## 判定要诀

1. **可复用 vs 模块专属**:同一条规则若"未来其它页面/模块也该遵循"→ 进 spec / cookbook;若只是"本模块的业务要求"→ 进该模块的需求文档。
2. **项目级 vs 跨项目**:只对本项目成立 → 进宿主的 spec;是通用的 PM Agentic 方法论 → 进 cookbook(skill / process / templates)。
3. **最小归属优先**:能进某条细则 spec,就不要进总纲;能进总纲就不要进规则文件。
4. **一条规则一个归属**:避免同一规则写进多处;必要时在主归属写正文,其它处只留指针。
5. **高冲突文件**(总纲、规则文件、依赖清单等):改动小、目的单一、先确认。
