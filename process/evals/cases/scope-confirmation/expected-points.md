# expected-points：范围界定

- [ ] S1 初划覆盖客户通讯信息、完整发运、订单创建、开票及付款后跨系统一致性全部原始要求，无静默排除。
- [ ] S2 独立客户通讯/订单创建/开票有各自业务结果；仅出库无业务出口的仓储加承运交接保留一个跨模块发运范围。
- [ ] S3 独立订单/开票外的付款结清端到端要求另提集成范围，仅含共同条件/结果，具名引用契约，不复制子范围标准。
- [ ] S4 范围表或等价结构有名称、结果、包含/排除、依赖/交叉、验收出口、确认状态，给推荐并停下请用户初步确认，未生成标准/PRD/测试。
- [ ] S5 建模验证发现候选拆分的出库/配送不能独立闭环、模型把出库当交付完成有错，建议回改边界及模型，交用户确认；不为分组重复造业务实体。
- [ ] S6 建模验证指出付款确认接口未就绪，Mock或子范围完成不能证明真实集成；未自行砍掉共同结果。
- [ ] S7 两分支均保持共享模型可复用、一范围多模型/PRD，跨模块主归集位置及协调方未定需确认，模块只索引；初划/建模验证/标准前最终确认三点可辨。

分支不可达要点按无法判定注明；S1–S4核初划，S5–S6核建模验证，S7分支分别核对。
