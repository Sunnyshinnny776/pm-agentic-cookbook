# notes：在用户项目中使用 cookbook

## 观察目标

观察 Agent 能否从产品使用入口进入 consistency-audit，守住领域、写入许可、配置、审计独立性和用户验收边界。请求本身不提示这些步骤。

## 隔离与证据

- 运行前冻结产品树、合成需求与 Domain Model、自然请求及判据的字节摘要。记录实际可用能力；能力缺失时，保留被试的实际说明与未执行路径作为判卷证据，不补入替代实现。
- 被试只看到中性宿主和正常产品文件。排除根级及 skill 级 evals；不复制答案、历史运行记录、个人规则和源仓库 Git 历史。
- 记录实际 harness、版本、模型声明、自动加载内容及 hook 配置边界；配置隔离未证实时如实标明，不能仅凭“新会话”宣称完全冷启动。
- 保存完整可见事件、读写路径、用户答复和最终产物。没有安装、没有写报告或没有派发独立执行者时，分别记录实际原因和未验证边界。
- 审查独立性相对被审文档的作者核对。若派发时的被试已是独立于原文作者的新执行上下文，可直接执行审查；不以额外子代理的层数作为独立性的证明。
- 独立判卷者仅写派发方指定的报告，读取冻结输入、判据、实际产物和事件，不改宿主、产品、夹具或判据。
- 原始成绩与之后的修订分别保存；修订输入或判据后，不沿用旧运行作为新字节的运行证据。

作者只提供用例，不参加被试执行或独立判卷。业务预期和最终验收由用户决定。
