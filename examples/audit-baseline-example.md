# 审计 baseline 示例：年度采购计划

本文用虚构的连锁零售数据演示 baseline、Oracle 映射和采集锚点如何配合。字段名、标识符和数值用于说明结构；它们不规定真实宿主的字段或业务口径。

## 三份材料分别回答什么

| 材料 | 回答的问题 | 内容 |
| --- | --- | --- |
| baseline | 这次核对固定使用哪份数据和初始状态 | 范围、版本、样本、恢复方式与未覆盖项 |
| Oracle 映射 | 某个核对点应该依据哪条已确认规则 | 验收标准、模型、PRD/spec 的具体位置与版本 |
| 采集锚点 | 从运行中的哪里取得该事实 | 页面、业务对象、可见字段及快照字段 |

baseline 记录现状和输入，预期行为仍以已确认 Oracle 为准。当前实现呈现了某种行为，只能证明它发生过；它是否正确需要另行核对。

## 一份 baseline 的内容

### 范围与版本

| 项 | 虚构取值 |
| --- | --- |
| 快照标识 | demo-2027-01 |
| 计划周期 | CYC-2027 |
| 包含 | 门店计划任务的列表、编制页及区域汇总入口 |
| 不包含 | OA 回调、付款、跨设备并发与性能 |
| 状态恢复入口 | 由运行宿主提供的示例数据恢复入口 |

记录快照的生成方式、版本或内容摘要。范围两侧都需要明确；未覆盖部分保留为未覆盖，不从“样本中没出现”推断它不存在。

### 固定的数据样本

```json
{
  "snapshotId": "demo-2027-01",
  "cycleId": "CYC-2027",
  "tasks": [
    {
      "id": "task-a",
      "organization": "东区一店",
      "status": "待提交",
      "plannedAmount": "12000.00"
    },
    {
      "id": "task-b",
      "organization": "西区一店",
      "status": "区域审核中",
      "plannedAmount": "8000.00"
    }
  ]
}
```

这份样本用于区分不同组织和状态。金额的精度、币种、合计方法和允许操作需要从宿主 Oracle 取得，不能从这两个数值推导出来。

### 可信度与依据

| 事实 | 证据位置 | 标记方式 |
| --- | --- | --- |
| 当前数据载有 task-a 和 task-b | baseline 中的 tasks 数组 | 数据快照事实 |
| 某页面显示了 task-a | 该次旅程的步骤与对象标识 | 运行观察，注明采集位置 |
| 当前用户可以编辑 task-a | 动作调用与状态结果 | 单独核验；仅有可见按钮不足以证明写入授权 |
| 跨组织访问是否应该被拒绝 | 宿主确认的权限与数据范围规则 | Oracle 期望，不能由当前按钮状态反推 |

现有来源冲突、缺少定位或只能推断的内容单列，不作为已经确认的回归约束。

## Oracle 映射示例

| 核对点 | 需要具名引用的依据 | 样本如何使用 |
| --- | --- | --- |
| 列表对象与组织归属一致 | 模型中的对象、组织关系与标识符 | 比较 task-a、task-b 的对象标识和组织字段 |
| 动作受角色与数据范围约束 | 权限矩阵及 Service 动作契约 | 分别选择组织管理员、组织协管员，记录对象范围与动作结果 |
| 操作后的状态符合规则 | 已确认的状态机及异常分支 | 对比操作前后状态，不能仅凭最终提示判断成功 |
| 下游汇总引用了正确版本 | 区域汇总的来源、版本和计算规则 | 核对来源对象与版本，不以页面显示某个合计作为正确性的证明 |

正式映射为每个依据填写实际文档路径、定位和版本，并引用验收标准的名称与编号。缺少已确认规则时，记录依据缺口并交用户裁定；不以此表替代需求定义。

## 采集锚点示例

| 语义 | 示例定位 | 需要记录的内容 |
| --- | --- | --- |
| 当前对象 | 当前详情对象或列表行的稳定标识 | task-a 或 task-b，关联组织 |
| 当前身份 | 当前生效角色及其数据范围 | 组织管理员或组织协管员及范围 |
| 当前状态 | 业务状态字段 | 操作前后的状态原值 |
| 当前可执行动作 | 动作入口与实际调用结果 | 可见性、可用性、拒绝原因、是否产生写入 |
| 相关数据 | 任务金额及来源版本 | 原始值及版本，避免只记录格式化展示文本 |

优先锚定业务对象与字段。CSS 选择器、行序号和按钮文案可以帮助定位，但不能替代对象身份；排序或换页后仍要确认当前行代表哪个对象。

## 使用边界

- 旅程前确认运行实例、数据版本和初始状态；多份录制产物不能无说明地混用。
- 原始输入可能含敏感数据。正式宿主决定采集范围、保存位置和留存方式，示例不要求公开真实快照。
- 数据恢复操作需要明确授权，不用人工补写结果来修饰一次失败的旅程。
- 从实际步骤核对跨页面数据、状态和权限；单元测试、结构检查与截图各自覆盖的内容分别记录。
- 作者实现、独立核对和用户验收分别记录。使用本示例不表示任何真实系统已经接受审计或验收。
